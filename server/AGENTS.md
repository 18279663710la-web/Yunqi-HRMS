# 服务端模块说明

## 模块定位
- Express REST API，服务于员工小程序和 Web 管理后台，使用共享 MySQL 数据库。

## 架构
- `src/index.ts` 在启用自动迁移时建库、更新结构并播种，再由 `src/app.ts` 装配中间件和路由。
- `admin/`、`miniprogram/` 按客户端及业务组织路由与各自的鉴权；`domains/` 保存跨端业务；`shared/db/` 提供连接池、结构初始化和种子，`shared/middleware/` 处理校验与错误。人事等部分路由仍包含 SQL 和事务，继续分层时须保持原事务边界。
- 薪资构成模型的 `fieldOrder` 可选，独立保存全部字段显示顺序；写入校验字段名完整且不重复，字段变动时保留现存名称顺序并追加新字段，排序变更不重写员工定薪。
- 员工与管理员使用独立鉴权；发票原图由 `/uploads` 提供，旧 OCR 入口为模拟实现，查验使用腾讯云 SDK。
- 入职表附件存于 `hr_onboarding_attachments`，按申请和字段归属并在提交时校验；员工在待填写申请期间上传，超级管理员受鉴权下载，打回及封存保留历史附件。提交时普通附件字段和表格子字段均最多 5 个文件、单个不超过 10MB。上传时普通字段已有 5 个则拒绝；表格同一列共用字段键，该列上限 250 个。超过上限只拒绝新上传，不删除已有文件。不得放入公开静态目录。
- `domains/u9/` 使用 SQL Server ODBC 按需查询 U9；绑定保存在 MySQL `u9_employee_bindings`，仅超级管理员维护。员工端按实时职务与绑定鉴权，应收和收款仅返回对应出货明细，汇总调用 U9 原报表并按客户当前负责人筛选；金额使用字符串保持精度，PDF 使用配置的中文字体。
- 职务目录存于 `job_titles`，员工主档的 `position` 是唯一现用职务；兼容 API 的 `jobCategory` 返回相同值，旧 `job_category` 列仅保留迁移资料。首次迁移按原分类确定员工职务、清理旧岗位目录并保存无职务快照的旧工资明细显示值；管理员维护职务，在用职务不可删除。
- 平级组织复用 `departments` 与员工 `dept_id`，`D00` 为未分配兼容节点；管理 API 提供组织创建、改名、删除及列表，在用组织不可删除。一次性迁移清除旧部门、将现有员工设为未分配并保存旧名称供人事异动历史展示；初始化不再创建模拟部门。历史引用的已删除组织不可撤销恢复。旧部门 API 保留兼容。
- `POST /api/invoices/image` 只保存发票图片，不运行 OCR；报销上传使用此接口。
- 董事长小程序账号独立保存，仅超级管理员可创建；仅可查看及处理分配给自己的申请，报销限已发布流程分配的单据。
- 新加班申请固定保存一项“补偿方式：加班费”，兼容旧客户端传入的选项；不改历史申请及工资计算规则。
- 自定义流程分支校验位于 `domains/approvals/expenseWorkflowPolicy.ts`，`customWorkflowService.ts` 按审批类型提供固定字段和条件：请假时长及假别、报销金额及类型、出差预算、采购预估金额，以及各类型自定义单选；加班通过自定义单选分支。保存设计稿时校验字段、条件有效性及同一分支节点下条件不重叠；发布后新申请按发布快照匹配分支。前端字段定义变动时须同步服务端校验和测试。
- `customWorkflowSimulation.ts` 检查流程结构并模拟测试用例路径；AI 测试只对配置地址发不含凭据和业务数据的 GET，收到 HTTP 响应即表示可达，不测试模型生成。
- 自定义审批流程独立设计稿按审批类型存于 `custom_approval_workflows`；超级管理员通过 `/api/admin/approval-workflows/:type` 读取与保存，保存校验结构、字段、条件及版本并记录操作日志。设计稿包含自定义表单字段、节点配置和分支连线条件；兼容旧画布，拒绝旧页面覆盖已有新配置。允许保存未完成设计稿；测试用例和结果分别存于 `custom_approval_test_cases`、`custom_approval_test_runs`，仅测试通过且流程、用例、固定表单版本均一致时可发布。发布快照及密文保存在 `custom_approval_publications`；新申请固定执行计划与密文快照，旧申请沿用原有流程。
- 报销设计稿支持 AI 节点，模型服务、地址、名称和规则保存在流程中；API Key 以 AES-256-GCM 加密存于 `custom_approval_credentials`，与流程同事务保存并随节点删除，读取只返回是否已配置。加密密钥可由 `WORKFLOW_CREDENTIAL_KEY` 提供，未提供时首次保存生成本地运行时密钥；迁移或备份数据库时必须安全保存相同密钥。`WORKFLOW_CREDENTIAL_KEY_FILE` 可指定本地密钥文件位置；密钥文件不纳入 Git。实际 AI 节点由独立队列异步调用节点配置的模型，失败三次后等待参与人手动重试，生成建议后流向人工审批；现有 AI 预审不使用节点配置。
- 超级管理员通过 `/api/admin/approval-workflows/:type/approver-candidates` 获取独立设计稿的候选人，包含启用的董事长和员工；已发布报销流程可分配董事长，旧报销单的董事长权限保持原限制。

## 目录结构
- `src/config.ts`：环境配置；`src/admin/`、`src/miniprogram/`：管理端和员工端接口；`src/domains/`：共享业务。
- `src/shared/`：数据库连接、迁移、种子、错误处理、类型与通用工具；双端鉴权位于各自客户端目录；`sql/schema.sql`：数据库结构；`scripts/`：接口冒烟脚本。
- `uploads/`：运行时上传文件。
- 管理端、小程序端、共享业务和基础设施下各子目录的具体职责见 `../docs/项目目录职责说明.md`；组织管理查询目前在 `admin/dashboard/`，不能仅按侧栏推断代码位置。

## 开发规范
- 使用 TypeScript、Express、mysql2、zod；沿用现有异步错误处理、统一响应和鉴权中间件。
- 除非用户明确要求调整架构，保持单进程服务及共享数据库，新增管理端和小程序端路由分别放入 `src/admin/` 和 `src/miniprogram/` 对应业务目录，不互换认证或越过权限校验。
- 跨端规则、服务与数据访问按业务放入 `src/domains/`，数据库、公共错误、请求校验和基础设施放入 `src/shared/`；仅单端使用的业务保留在该端对应模块。不得新建集中所有业务的全局 `services/` 目录。
- 逐步使路由承担 HTTP 参数、权限及响应，业务服务承担业务流程，数据访问承担 SQL；沿用现有统一异常处理和响应格式，保持事务连接、操作顺序、行锁、并发控制及审计语义。历史路由尚未全部分层，按修改范围渐进处理。
- 业务或目录变化时同步维护当前目录 README、相关父目录 README、模块说明和项目目录职责总览；只记录实际实现和已验证命令，不把计划中的分层写成现状。
- 配置从环境读取，敏感值不得写入文档；依赖由本模块 `package.json` 和锁文件管理。
- U9 连接可配置 `U9_SQL_DRIVER`、`U9_SQL_SERVER`、`U9_SQL_DATABASE`，使用运行服务进程的 Windows 身份；`U9_PDF_FONT` 可指定中文字体。SQL Server 账号应由数据库管理员限制为查询所需对象及报表过程的权限，连接字符串的只读意图本身不构成权限控制。
- U9 回款通知轮询可配置 `U9_RECEIPT_NOTIFY_ORG_CODE`（默认 001）、`U9_RECEIPT_NOTIFY_SINCE`、`U9_RECEIPT_NOTIFY_LOOKBACK_DAYS`、`U9_RECEIPT_NOTIFY_POLL_MS`；轮询与留单规则见 `src/domains/u9/README.md`，不得扩大 U9 只读范围。客户联想的拼音字段由 `pinyin-pro` 在服务端生成。
- 日志沿用现有服务前缀；统一格式化规范待确认。

## 常用命令
- 在本目录运行 `npm install`、`npm run dev`、`npm run build`、`npm run typecheck`。
- `npm run db:setup` 初始化；服务运行时可执行 `npm run smoke`、`npm run smoke:admin`。

## 修改指南
- 项目功能优化暂时收尾；后续按用户明确提出的需求维护，保持现有业务、数据与接口兼容并验证受影响范围。阶段性收尾不表示待确认事项或未实现功能已经完成。
- 业务员 U9 业务模块功能与性能优化均已暂时收尾，**后续不得修改该模块**：`src/domains/u9/`、`src/miniprogram/business/`、`src/admin/employees/u9Routes.ts` 的查询口径、归属与鉴权隔离、回款通知、接口契约、PDF 样式，以及 MySQL 镜像 ETL/网关/缓存（`U9_ETL_ENABLED` / `U9_QUERY_SOURCE`）均不再改动，除非用户提出硬性且明确的修改要求。现状为员工默认可读镜像、抽取单表分查后应用层拼接，见 `src/domains/u9/README.md`。涉及共享职务、鉴权、数据库或接口时须保持兼容并验证受影响链路。U9 原报表导出尚未接入。
- 薪资构成模型、工资批次、工资发放、工资发放记录目前暂时收尾。后续优化其他模块时，不得改变这四个模块的现有业务逻辑，除非用户提出硬性且明确的修改要求。保护范围包括计算口径、字段与数据流、接口行为、批次复核及发放、工资条发送与下载、历史快照和导出；涉及共享代码、数据或接口时须保持这些行为兼容，并针对受影响链路验证。若其他需求确实必须改变上述逻辑，先说明影响并取得用户的明确要求，再修改。
- 工资条由超级管理员发放批次时自动发送：按管理员和数据版本暂存每人 PDF，事务锁批次、验证版本及文件齐全后同时保存发放快照与全部工资条；不完整或冲突时回滚。PDF 保存在 `hr_payroll_payslips`，重发替换文件并递增提醒版本；超过一天的暂存文件在后续准备或服务启动时清理。员工列表、下载和已读接口只返回本人数据，下载不缓存、令牌不进入 URL；已读须匹配提醒版本。
- 变更 API、权限或数据结构时检查两端调用、schema、迁移和初始化逻辑。
- 启动可能写入演示数据；`db:reset` 会重置数据库，冒烟脚本也可能写数据，运行前确认目标环境。
- 演示员工固定为三类职位各一名负责人和一名普通员工；初始化不再生成模拟审批，旧样本标识仅用于安全清理。
- `attendance_settings` 保存初始打卡时段、具体休息日期和 GCJ-02 打卡点坐标与半径，仅在没有任何考勤组时生效；`attendance_groups` 保存各考勤组（不分类型，名称、时段、公司日历、坐标与半径），`attendance_group_employees` 保存员工归属，同一员工只属于一个组；`company_calendar_rules` 保存多条公司日历，支持不固定、每周固定、按周轮换及例外休息/上班日期，考勤组必须选择一条。上下班卡时间段可自由设置，服务端校验两段各自顺序且上班卡时间段不能重合或晚于下班卡时间段；中间时段不在任何打卡窗口。未分配员工使用第一个考勤组（按创建顺序），无组时回退初始设置，删除组后成员按同一规则回退。员工端、管理端、仪表盘、工资取数及入职任务排期均按同一日历解析结果；服务端校验休息日、定位和精度，上下班卡可独立打卡。公司日历接口位于 `admin/models-formulas/companyCalendarRoutes.ts`，读取对所有管理员开放，维护仅限超级管理员。
- 普通考勤状态为正常、未打上班卡、未打下班卡、缺卡、请假、休息、出差；出差与请假均由已通过审批按申请起止日期实时解析（`travelAttendanceService.ts`、`leaveAttendanceService.ts`，字段缺失时回退摘要），状态优先级为管理员手工登记 > 出差 > 日历休息日 > 请假；出差日与请假日均免打卡，出差计入出勤，请假按缺勤参与绩效。加班由独立打卡记录叠加展示并可单独筛选。旧的 09:30 迟到判断保留为内部统计字段，不作为展示状态。
- `attendance_overtime_punches` 按已通过的本人加班申请独立保存一组上下班时间；上班卡从申请日期及开始时间起开放，下班卡无结束时限，可跨日；两次打卡均须通过现有地点校验，同一员工同时只能有一组未结束的加班卡。时长按实际两次打卡计算，并归入上班卡日期。
- `attendance_visits` 保存员工单次拜访签到，时间由服务端生成；`attendance_visit_photos` 保存 1–3 张现场照片（未提交时为未归属状态），照片按员工隔离，本人和管理端可读取。拜访地址通过腾讯位置服务 WebServiceAPI 逆解析为地图地点名称和格式化地址，Key 从 `TENCENT_MAP_KEY` 读取，需在控制台开启 WebServiceAPI 并分配逆地址解析额度；未配置、额度用尽或调用失败时回退“当前位置”，页面不展示经纬度。拜访记录仅用于查询和导出，不参与考勤状态、月度汇总或工资计算。工作台快捷入口来自 `quick_actions`，启动迁移把旧“公告通知”替换为“拜访登记”，公告页面和数据保留。
- 管理考勤接口支持按月份或 `date` 查询单日；单日查询包含无打卡记录的员工，沿用相同状态规则，拒绝未来日期。
- 请假、报销、加班、出差、采购分别由超级管理员配置一名审批人；未配置或账号不可用时禁止提交。请假、加班、出差及采购可选择董事长或已启用小程序账号的员工，报销选择员工；审批人可审批自己发起的申请。
- 请假时长按自然时间差计算，不足一天记 1 天，超过一天的余数满 12 小时进 1 天；服务端重新计算表单、标题和摘要，并拒绝无效起止时间。
- 请假审批通过后按申请起止日期联动考勤“请假”状态；普通员工的“已办结”列表及详情接口尚未按申请参与人限制，后续变更审批权限时需处理。
- 审批操作和撤销通过事务锁定单据，避免并发处理覆盖状态；历史单据的审批节点不会因负责人变更自动改派。
- `approval_approvers` 按审批类型保存审批人，配置接口仅超级管理员可访问并记录操作日志；请假、加班、出差及采购支持独立董事长账号，员工候选需启用小程序账号。新单据保存提交时的审批人快照，历史单据不改派。
- `approval_rules` 保存报销审批规则文本，仅超级管理员可读取和修改，更新操作记日志；新报销单将提交时规则保存为 AI 建议快照。
- 人事管理接口位于 `/api/admin/hr`，所有接口仅超级管理员可访问。未匹配的路径在通过超级管理员校验后返回 404，不再落到员工鉴权。入职表配置、申请和员工分项资料分别保存于 `hr_settings`、`hr_onboarding`、`hr_employee_records`。新工资发放记录按批次保存于 `hr_payroll_disbursement_records`，旧员工级记录表不再使用；日志不记录工资或个人资料内容。
- 劳动合同的编号、开始日期、结束日期为必填，校验日期有效性及先后；文件保存在 `hr_contract_files` 的数据库二进制字段，支持 PDF、DOC、DOCX、JPG、PNG，单文件不超过 10MB，仅超级管理员可按员工上传、列出和下载。每次导入保留独立记录，不自动关联合同信息历史版本。
- 历史入职申请仍可通过 `GET /api/admin/hr/onboarding` 只读查询。旧登记、任务、确认建档和任务模板写入接口已移除；`hr_onboarding`、`hr_onboarding_tasks`、`hr_onboarding_links` 及历史数据保留。单模板公开接口 `GET/PUT /api/admin/onboarding-form/template` 已移除，模板维护使用 `/api/admin/onboarding-form/templates`。
- 人事事件保存在 `hr_events`，仅记录不自动更改员工资料；合同与定薪更新时在事务内写入 `hr_employee_history`，首次修改旧资料会先保存旧快照。保存定薪忽略请求中的职务，不修改 `employees.position`。
- 旧入职任务模板及任务数据仍保留，Web 已移除模板入口。
- 新员工自助申请使用 `hr_self_onboarding`；多模板保存于 `hr_onboarding_form_templates`，旧单模板保留为模板 1；默认模板编号保存在 `hr_settings`。登记时复制字段快照，员工接口仅可读取和提交本人待填写申请，服务端校验字段类型、必填和限制。旧入职申请数据不迁移、不删除。
- 离职申请表模板保存于 `hr_offboarding_form_templates`，现用模板编号为 `hr_settings.self_offboarding_default`，修改历史在 `hr_offboarding_form_template_history`；管理接口 `/api/admin/offboarding-form/templates*` 仅超级管理员，字段校验复用入职表 schema。本阶段仅模板配置，不含登记申请或员工填写。旧交接清单接口已移除，`hr_offboarding` 与 `hr_offboarding_tasks` 仍保留。
- 模板保存名称和 `version`，编辑需携带版本，冲突返回 409；现用模板和最后一个模板禁止删除。初始模板仅在模板表为空时创建，不再强制 id=1；默认模板缺失时回退到编号最小的模板。
- 模板新建、修改、删除在事务内写入 `hr_onboarding_form_template_history`，保存操作前后名称和字段、操作人及时间；删除模板不影响申请快照。
