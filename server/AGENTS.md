# 服务端模块说明

## 模块定位
- Express REST API，服务于员工小程序和 Web 管理后台，使用共享 MySQL 数据库。

## 架构
- `src/index.ts` 在启用自动迁移时建库、更新结构并播种，再由 `src/app.ts` 装配中间件和路由。
- `admin/`、`miniprogram/` 按客户端及业务组织路由与各自的鉴权；`domains/` 保存跨端业务；`shared/db/` 提供连接池、结构初始化和种子，`shared/middleware/` 处理校验与错误。人事等部分路由仍包含 SQL 和事务，继续分层时须保持原事务边界。
- 薪资构成模型的 `fieldOrder` 可选，独立保存全部字段显示顺序；写入校验字段名完整且不重复，字段变动时保留现存名称顺序并追加新字段，排序变更不重写员工定薪。
- 员工与管理员使用独立鉴权；发票原图由 `/uploads` 提供，旧 OCR 入口为模拟实现，查验使用腾讯云 SDK。
- `POST /api/invoices/image` 只保存发票图片，不运行 OCR；报销上传使用此接口。
- 董事长小程序账号独立保存，仅超级管理员可创建；其接口权限限于本人参与的请假、加班、出差及采购审批。

## 目录结构
- `src/config.ts`：环境配置；`src/admin/`、`src/miniprogram/`：管理端和员工端接口；`src/domains/`：共享业务。
- `src/shared/`：数据库连接、迁移、种子、错误处理、类型与通用工具；双端鉴权位于各自客户端目录；`sql/schema.sql`：数据库结构；`scripts/`：接口冒烟脚本。
- `uploads/`：运行时上传文件。
- 管理端、小程序端、共享业务和基础设施下各子目录的具体职责见 `../docs/项目目录职责说明.md`；组织管理查询目前在 `admin/dashboard/`，不能仅按侧栏推断代码位置。

## 开发规范
- 使用 TypeScript、Express、mysql2、zod；沿用现有异步错误处理、统一响应和鉴权中间件。
- 除非用户明确要求调整架构，保持单进程服务及共享数据库，新增管理端和小程序端路由分别放入 `src/admin/` 和 `src/miniprogram/` 对应业务目录，不互换认证或越过权限校验。
- 跨端规则、服务与数据访问按业务放入 `src/domains/`，数据库、公共错误、请求校验和基础设施放入 `src/shared/`；仅单端使用的业务保留在该端对应模块。不得新建集中所有业务的全局 `services/` 目录。
- 逐步使路由承担 HTTP 参数、权限及响应，业务服务承担业务流程，数据访问承担 SQL；沿用现有统一异常处理和响应格式，保持事务连接、操作顺序、行锁、并发控制及审计语义。历史路由尚未全部分层，按修改范围渐进处理。
- 业务或目录变化时同步维护当前目录 README、相关父目录 README、模块说明和项目目录职责总览；只记录实际实现和已验证命令，不把计划中的分层写成现状。
- 配置从环境读取，敏感值不得写入文档；依赖由本模块 `package.json` 和锁文件管理。
- 日志沿用现有服务前缀；统一格式化规范待确认。

## 常用命令
- 在本目录运行 `npm install`、`npm run dev`、`npm run build`、`npm run typecheck`。
- `npm run db:setup` 初始化；服务运行时可执行 `npm run smoke`、`npm run smoke:admin`。

## 修改指南
- 变更 API、权限或数据结构时检查两端调用、schema、迁移和初始化逻辑。
- 启动可能写入演示数据；`db:reset` 会重置数据库，冒烟脚本也可能写数据，运行前确认目标环境。
- 演示员工固定为三类职位各一名负责人和一名普通员工；初始化不再生成模拟审批，旧样本标识仅用于安全清理。
- `attendance_settings` 保存办公时间、同日上下班打卡时段、具体休息日期和 GCJ-02 打卡点；服务端校验时段、休息日、定位和精度，上下班卡可独立打卡。
- 普通考勤状态为正常、未打上班卡、未打下班卡、缺卡、请假、休息；加班由独立打卡记录叠加展示并可单独筛选。旧的 09:30 迟到判断保留为内部统计字段，不作为展示状态。
- `attendance_overtime_punches` 按已通过的本人加班申请独立保存一组上下班时间；上班卡从申请日期及开始时间起开放，下班卡无结束时限，可跨日；两次打卡均须通过现有地点校验，同一员工同时只能有一组未结束的加班卡。时长按实际两次打卡计算，并归入上班卡日期。
- 管理考勤接口支持按月份或 `date` 查询单日；单日查询包含无打卡记录的员工，沿用相同状态规则，拒绝未来日期。
- 请假、报销、加班、出差、采购分别由超级管理员配置一名审批人；未配置或账号不可用时禁止提交。请假、加班、出差及采购可选择董事长或已启用小程序账号的员工，报销选择员工；审批人可审批自己发起的申请。
- 请假时长按自然时间差计算，不足一天记 1 天，超过一天的余数满 12 小时进 1 天；服务端重新计算表单、标题和摘要，并拒绝无效起止时间。
- 请假审批通过暂不自动更新考勤；普通员工的“已办结”列表及详情接口尚未按申请参与人限制，后续变更审批权限时需处理。
- 审批操作和撤销通过事务锁定单据，避免并发处理覆盖状态；历史单据的审批节点不会因负责人变更自动改派。
- `approval_approvers` 按审批类型保存审批人，配置接口仅超级管理员可访问并记录操作日志；请假、加班、出差及采购支持独立董事长账号，员工候选需启用小程序账号。新单据保存提交时的审批人快照，历史单据不改派。
- `approval_rules` 保存报销审批规则文本，仅超级管理员可读取和修改，更新操作记日志；新报销单将提交时规则保存为 AI 建议快照。
- 人事管理接口位于 `/api/admin/hr`，所有接口仅超级管理员可访问；入职表配置、申请、员工分项资料和工资发放登记分别保存于 `hr_settings`、`hr_onboarding`、`hr_employee_records`、`hr_payroll_records`。同一员工同一工资月份只能登记一次；工资发放登记不执行转账，日志不记录工资或个人资料内容。
- 劳动合同的编号、开始日期、结束日期为必填，校验日期有效性及先后；文件保存在 `hr_contract_files` 的数据库二进制字段，支持 PDF、DOC、DOCX、JPG、PNG，单文件不超过 10MB，仅超级管理员可按员工上传、列出和下载。每次导入保留独立记录，不自动关联合同信息历史版本。
- 入职任务和建档关联分别保存在 `hr_onboarding_tasks`、`hr_onboarding_links`；确认建档时锁定申请并在同一事务检查必需任务、创建员工和关联申请，不自动开通账号；建档后仍可继续办理其他入职任务，任务进度与建档状态独立。
- 入职任务模板保存在 `hr_settings`，应用到无任务申请时复制为独立任务。人事事件保存在 `hr_events`，仅记录不自动更改员工资料；合同与定薪更新时在事务内写入 `hr_employee_history`，首次修改旧资料会先保存旧快照。
- 旧入职任务模板及任务数据仍保留，Web 已移除模板入口。
- 新员工自助申请使用 `hr_self_onboarding`；多模板保存于 `hr_onboarding_form_templates`，旧单模板保留为模板 1；默认模板编号保存在 `hr_settings`。登记时复制字段快照，员工接口仅可读取和提交本人待填写申请，服务端校验字段类型、必填和限制。旧入职申请数据不迁移、不删除。
- 模板保存名称和 `version`，编辑需携带版本，冲突返回 409；现用模板和最后一个模板禁止删除。初始模板仅在模板表为空时创建，不再强制 id=1；默认模板缺失时回退到编号最小的模板。
- 模板新建、修改、删除在事务内写入 `hr_onboarding_form_template_history`，保存操作前后名称和字段、操作人及时间；删除模板不影响申请快照。
- 超级管理员可通过 `POST /api/admin/onboarding-form/applications/:id/return` 打回已提交申请；事务加锁并将原模板及完整提交存入 `hr_self_onboarding_submissions`，再以打回时现用模板生成重填快照；员工重新填写后提交。旧的待重填申请迁移到当前模板，历史原模板归档。管理员不能直接修改申请；旧版管理员修改历史 `hr_self_onboarding_edits` 保留可查。
- 已提交的自助申请可由超级管理员封存；锁行检查并记录封存时间和管理员，封存后不可打回或再次提交。个人档案仅通过受权限保护的接口读取已封存申请；旧 profile 写入接口禁用，原数据保留。
- 存在待填写入职申请的员工，仅可访问本人信息和入职申请查询、提交接口；其他员工业务接口返回入职待完成状态，提交成功后恢复访问。董事长不受此限制。
- 申请模板支持表格字段及文字、数字、日期、单选项子字段，最多 50 行；单选字段保存 1–30 个选项，选项去空格后不能为空或重复，提交值必须属于选项。照片和签名使用经大小、格式和文件头检查的图片数据，与声明及确认状态一并保存在申请数据中，仅通过已鉴权的人事管理接口读取。旧申请格式仍可读取。
- 全员出勤绩效规则支持比例/天数与出勤/缺勤的四种组合，当前配置存于 `hr_settings.payroll_attendance_rule_config`；切换方式后保存替换当前规则。按比例出勤沿用 100–100 全勤及连续闭环旧格式并同步旧键 `payroll_attendance_rules`；其他模式按下限升序连续覆盖、含下限不含上限，缺勤比例最后上限 100% 包含 100%，天数为非负整数且最高区间无上限。旧规则可通过新接口读取；新模式启用时旧读取接口返回 409，旧接口保存会切回按比例出勤。旧员工规则迁移及多套冲突检查保留。配置不执行算薪或重算批次。
- 工资批次新增明细按固定模型数字字段用途计算，不自动叠加出勤或加班绩效；未绑定考勤的扩展数字字段默认 0、字符串字段默认空，按收入、扣款、仅记录类别计算，保存时校验类型和金额范围。规则保存不重算草稿或历史记录。
- 可选择已复核工资批次登记发放：在事务中按批次月份和各明细实发金额写入 `hr_payroll_records` 并保存批次编号；任一员工同月已登记则全部回滚。原有员工手工登记与历史记录保留。
- 工资明细创建与一键预览使用当前事务批量读取所选考勤数据；出勤复用现有汇总口径，加班统计已审批、完整打卡的实际时长并归属上班卡月份（小时保留两位小数，包含加班费和调休）。缺少考勤记录、单卡或未完成加班打卡时报错；没有加班记录返回 0。明细保存来源、数据项目、批次月份和取值，自动获取的扩展字段不可手改，复核后不重算。
- 一键添加使用 `/payroll-batches/:id/auto-preview` 只读预览、`/payroll-batches/:id/auto-items` 事务写入；员工须有已封存入职表、完整合同及定薪生效日期。单独添加只要求有效定薪。固定字段按名称取值并按用途计算，缺失数字为 0、文本为空；批次内已存在的员工跳过。
- 加班绩效规则保存在 `hr_settings.payroll_overtime_rules`，规则配置和加班打卡继续保留，但不自动应用到工资批次，工资批次的加班重算接口已移除。
- 薪资构成模型经 `/api/admin/hr/salary-model` 读写，全站单套模型；固定组含姓名、员工号、职务三个不可删除的字符串身份字段。其他固定及扩展字段可设数字/字符串、收入/扣款/仅记录，字符串只能仅记录；考勤来源可选择实际出勤天数或实际加班时长，字段必须为数字且仅记录；旧配置未选具体项目时继续保留但不查询。旧固定数字字段默认收入，旧扩展字段默认仅记录。固定组变动按名称同步员工定薪，类型变更须无损转换，否则事务回滚；新工资明细保存模型字段及用途快照，编辑带版本防并发覆盖，历史明细保留。显示设置保存为 none/display/output（缺省为 none），包含身份字段；当前不影响业务行为，仅变更显示设置时不重写员工定薪。
- 薪资发放流程经 `/api/admin/hr/payroll-workflow` 读写（GET/PUT），仅超级管理员可访问；单份流程保存在 `hr_settings.payroll_workflow`，含版本、节点位置和连线。节点类型限定为系统算薪、手动调整、复核、输出工资条、发送到对应员工的小程序端、导入其他字段；连线校验端点存在、禁止自连和重复，节点/连线上限 200/400。写入锁定配置并校验版本，暂不执行实际算薪或发放。
- 离职清单和任务使用 `hr_offboarding`、`hr_offboarding_tasks`，同一员工不能同时存在多个办理中清单；完成清单本身不自动停用账号或移交审批。
- 清单完成且最后工作日已到后，超级管理员可明确确认离职；须先更换该员工作为指定审批人的配置并处理其待处理申请和审批。确认写入 `hr_employee_departures`、停用账号并撤销令牌；撤销离职保留记录且不自动启用账号。审批提交、审批人设置和离职确认使用员工行锁防止并发遗留待办。
- 已确认离职员工不计入当前仪表盘人数或员工通讯录；考勤查询保留最后工作日及以前的历史，不为离职后日期生成记录。员工管理保留档案并标注离职。
- 调岗和晋升记录在 `hr_employee_transitions`：提交时锁定并更新员工的岗位、职级、职位分类或部门，撤销仅允许当前最新未撤销记录且当前值与变更后快照一致；不得处理未来日期。参考来源及尚未实现的上游逻辑见 `third_party/frappe-hr/NOTICE.md`。
- 员工访问和刷新令牌会校验账号启用状态及 `employee_session_versions`；账号停用、更新账号凭据或重置密码时在同一事务递增会话版本，使旧令牌失效。董事长账号沿用独立认证。
- AI 建议使用服务端生成的规则编号对应规则快照原文，避免模型改写造成误判；有充分证据时建议同意，关键材料不足或不合规则时建议驳回并说明原因。无效编号或模型响应异常按服务失败处理，不伪造建议。
- 报销经真实验伪与事务内查重后，事务内创建 `expense_ai_jobs`；后台任务调用 DeepSeek 或配置的本机兼容接口，仅生成辅助建议，不改变审批状态。仅该单据指定审批人可读取结果，规则缺失、模型未配置或失败时仍可人工审批。
- 员工报销提交前可请求 `POST /api/approvals/expense-precheck/stream`：服务端校验图片归属、发票查重和真实验伪后，使用当前报销规则流式生成预审；不会创建审批单或占用发票。流式文本为临时建议，最终结果需验证规则依据；缺失材料及不合规范的材料可分别返回。原非流式接口保留兼容。
- 图片上传归属记录在 `expense_uploads`，补充材料关联在 `expense_attachments`；AI 只读取申请人本次提交中属于其账户的服务端本地上传图片。扫码无原图时仅提供发票字段；图片无法读取或过大时返回人工复核。
- `EXPENSE_AI_DRIVER`、`EXPENSE_AI_BASE_URL`、`EXPENSE_AI_MODEL` 和 `DEEPSEEK_API_KEY` 从本地环境配置读取；本地模型仅允许本机地址，密钥不记录在文档中。AI 使用的规则、材料及查验信息以提交时快照为准。
- 报销至少包含一张非模拟发票：数电票按 20 位号码、传统票按 10/12 位代码加 8 位号码识别；审批中或已通过的发票阻止重复提交，驳回或撤销后可重新提交。
- 发票查重在提交事务内再次执行，按 `invoice_identity_locks` 的规范化身份加锁以防并发重复提交；历史缺少代码的传统票记录按号码保守匹配。查验接口先查重，再使用腾讯云 SDK，15 分钟内仅复用一致的真实查验成功结果；报销提交必须通过服务端真实查验。
- 腾讯云配置优先读取 `server/.env.local`，其次读取 `server/.env`；`VERIFY_DRIVER=tencent`，密钥由环境变量提供，勿记录到仓库。未配置凭证、异常票据或状态不明时禁止报销提交；当前支持 20 位数电票和明确票种的电子普票、专票，真实票联调待完成。
- 新审批保存提交时的职位分类；旧单据如保存的是旧岗位名称则展示员工当前职位分类，员工不存在时保留原值。
- 小程序演示重置保留审批和发票；完整 `db:reset` 仍会清空数据库业务数据。
- 原配置的打卡时段结束时间迁移后为空，需管理员补充；未选择的日期（包括周末）不自动视为休息日。

- 自助入职提交必须使用包含 `declarationAccepted: true` 的新格式并提供有效手写签名；未确认、未签名或旧格式提交均拒绝，已保存的历史申请保留原样。
