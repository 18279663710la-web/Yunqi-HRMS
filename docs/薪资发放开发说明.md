# 薪资发放开发说明

## 当前状态与保护约束

薪资构成模型、工资批次、工资发放、工资发放记录目前暂时收尾。后续优化其他模块时，不得改变这四个模块的现有业务逻辑，除非用户提出硬性且明确的修改要求。保护范围包括计算口径、字段与数据流、接口行为、批次复核及发放、工资条发送与下载、历史快照和导出；涉及共享代码、数据或接口时须保持这些行为兼容，并针对受影响链路验证。若其他需求确实必须改变上述逻辑，先说明影响并取得用户的明确要求，再修改。

## 功能与权限

Web 人事管理分为工资批次、工资发放和工资发放记录三个独立页面，仅超级管理员可访问。同月允许多个批次，列表和导出文件名使用批次编号区分；员工只能出现在同月一个已复核批次，不同草稿可以暂存同一员工，添加及复核时校验，复核冲突需删除重复明细。管理员可创建工资批次并添加及复核明细。工资发放页面无标题及外围卡片，可选择当月已复核批次、编辑补充项、输出或登记发放；发放后批次只读，记录按批次汇总并可查看快照。

## 薪资发放流程画布

- 位于“模型与公式 → 薪资发放流程”，使用 React Flow 画布。
- 预设六种节点：系统算薪、手动调整、复核、输出工资条、发送到对应员工的小程序端、导入其他字段。同一类型可多次添加。
- 主导航全局固定为仅图标，子栏目侧栏规则不变；点击模块时主菜单选中态移动到该模块，子栏目宽度按最长子模块名称动态计算。画布填充标题下方的可用空间，空间不足时保留最小高度并允许纵向滚动。支持从左侧一级工具条点击加号打开二级节点面板，将节点拖入画布，或点击节点后让预览跟随鼠标、再次点击画布放置；点击节点后二级面板自动收起。工具条同时提供选择和平移模式；节点可移动，从输出端口连接到输入端口，Delete 删除节点/连线，支持缩放平移和保存。
- 连线只做基础校验：禁止节点自连、禁止同一对节点重复连线；暂不校验环路。
- 单份流程保存在 `hr_settings.payroll_workflow`，包含版本、节点位置和连线；刷新后恢复。版本用于防止并发覆盖。
- 当前仅保存流程结构，节点功能尚未接入算薪、复核、工资条、小程序通知或字段导入。

## 模型和工资口径

- 固定薪资模型包含姓名、员工号、职务三个字符串身份字段及可配置的数字或字符串字段；职务取员工主档岗位。固定模型保存时员工定薪按字段名同步：同名保留、新增数字为 0、字符串为空、删除移除；类型变更只允许无损转换，无法转换时事务回滚。
- 固定和扩展字段均可配置数字或字符串，以及“收入”“扣款”或“仅记录”；字符串只能选择仅记录。考勤系统弹窗分别选择数据项和计算规则：出勤天数、加班时长直接输出为数字仅记录；出勤天数可绑定出勤绩效、加班时长可绑定加班绩效，结果为数字收入，每种绩效最多绑定一个字段。旧加班费数据项继续按原口径计算；旧配置未选择数据项目时保留但不查询。
- 新增工资明细时，系统从员工当前定薪中按名称取得固定字段；模型收入字段加总并减去模型扣款得到应发，仅记录字段不参与。工资批次列表、合计和导出仅显示应发；服务端保留历史独立扣除与实发。草稿可编辑非身份固定字段（含考勤和绩效结果）及未绑定考勤的扩展字段；考勤来源扩展字段、姓名、员工号和职务只读。固定字段覆盖仅影响当前明细，保留首次原值、修改人、时间及考勤依据，不写回定薪或考勤，不联动其他字段。输入时预览行和批次应发，回车或失焦保存，Esc 取消。保存失败或并发冲突保留输入。旧草稿首次同步时清零原自动汇总的扣除，模型保存时同步草稿中同名同组字段用途并重算；字段值及考勤计算快照保留，已复核明细不变。同步后金额无效时阻止操作并回滚。历史没有模型快照的明细保留原金额，不提供编辑。
- 应发 = 固定和扩展收入字段之和 − 固定和扩展扣款字段之和；服务端仍保留历史手工填写的独立扣除，实发 = 应发 − 扣除，工资批次页面已移除独立扣除编辑入口。仅记录字段不计入金额，金额按分计算，超出范围或扣除超过应发时拒绝保存。
- 工资批次明细及一键添加预览使用当前薪资模型保存的字段顺序，包含姓名、员工号及职务；已从模型移除但存在于明细快照中的字段追加显示。排序只影响展示，不改变快照或金额。
- 工资批次调用薪资模型规则，不单独配置各字段的计算方式。考勤来源目前使用同库的考勤数据：创建和预览明细时校验员工号非空且唯一，以员工号关联内部员工 ID，并按批次月份获取数据；快照记录员工号、月份、数据和计算依据。接口数据在明细创建后不自动刷新，当前没有独立外部考勤系统连接。
- 考勤取值以工资批次月份和员工为参数，在单人添加、一键添加预览及确认写入时查询，确认时重新读取。工资出勤统计按当前休息日设置，只计状态不是休息、出差或请假且上下班卡齐全的天数，再加上已通过的出差日；请假日即使留有上下班时间也不计入。普通单卡计 0 出勤天，不阻止算薪，并按缺勤参与绩效。考勤页面和小程序保留原有单卡状态及汇总。指定月份没有考勤记录会提示核实。加班时长统计已通过审批且打卡完整的实际时间（包括加班费及调休），按上班卡日期归属月份，小时数四舍五入保留两位小数；未结束打卡提示处理，无加班记录为 0。查询失败或加班未结束会阻止创建，批量操作不会部分写入。已保存明细和已复核、已发放快照不因这次口径变化改写。
- 保存的工资明细快照包含考勤来源、项目、月份和取值；考勤变化不会自动修改已创建的明细或已复核批次。
- 已绑定出勤或加班绩效规则的字段在新增明细时计算并计入收入；出勤绩效的负调整减少应发。修改规则不重算已有明细，已复核批次不能修改。
- 单独添加要求员工有定薪生效日期；一键添加还要求入职表已封存且合同编号、起止日期完整。批次内已有员工跳过；一键预览不写库，确认时事务内重新读取并计算。

固定和扩展字段（包括身份字段）可设置显示方式：无、仅显示、仅输出，缺省为无。目前该设置仅保存于薪资模型，不改变工资批次展示、计算或输出。

## 工资批次输出

- 工资批次操作栏的“输出”可下载当前批次的 XLSX 或 PDF，包含全部已保存的员工明细、薪资模型字段、历史快照独有字段和应发合计，不受页面分页影响；有未保存单元格编辑时禁止输出。
- 工资表使用居中标题、工资月份、字段编号和网格；合计行前三列合并显示“本批次合计”，中间字段合并，应发列单独加宽。显示设置当前不筛选导出字段。
- XLSX 保留数字类型；PDF 根据同一份 XLSX 工作表的列宽、行高、合并单元格和样式由浏览器绘制，全部列放在同一页宽，员工较多时纵向分页。PDF 是图像内容、文字不可选，且并非 Excel 原生转换，字体和间距可能存在细微差异。
- 相关实现位于 `web/src/modules/hr/payroll/payrollExportData.ts`、`payrollExportXlsx.ts`、`payrollPdfLayout.ts` 和 `payrollExportPdf.ts`；导出时不修改工资数据。

## 工资发放

- 工资发放页面按月份选择已复核批次，更换月份清除选择；原明细只读，按现用模型排序并追加历史快照字段；补充项在表格、发放记录及 PDF/XLSX 输出中均位于应发之前。应发及实发合计紧随表格末行。输出复用工资批次的 PDF/XLSX 格式，包含全部员工、补充项和两项合计；发放记录及输出中的应发、实发表头上边界对齐。发放时管理端根据当前数据版本逐人生成并暂存仅含本人明细、不含批次合计行的 PDF；服务端核对版本及每人文件，在同一事务内登记发放并发送工资条，失败不发生部分发放。已发放批次可逐人重新生成并发送工资条，更新文件及未读提醒。小程序工作台弹出提醒，个人中心可查看历史和通过微信 PDF 查看器菜单保存。
- 顶部可为已复核批次新增数字补充项，字段全批次共用，各员工金额独立填写，初始为 0；收入加到应发、扣款从应发减去、仅记录不参与，实发可以为负。金额按分计算，原批次的历史独立扣除和实发不参与本页计算。
- 发放前核对当前快照版本，事务内锁定批次并保存原明细、补充项、薪资模型及金额汇总；每个批次只能发放一次，发放后禁止修改补充项。记录列表按批次显示类型、月份、应发、实发、备注和登记时间；点击月份打开独立页签，只读展示发放时的完整工资表。发放是系统登记，不执行付款；备注为空。
- 字段保存名称、必填、用途及显示设置，显示设置目前仅保存；金额支持回车或失焦保存、Esc 取消，并发冲突保留输入并刷新后重试；保存和后台刷新保留横向滚动位置，浏览器刷新恢复经验证的已选批次及位置，切换月份清除记录；会话存储不包含金额或未提交输入。字段和值独立入库，仅超级管理员访问；暂存文件按管理员和版本隔离，成功后删除，超过一天的文件在后续准备或服务启动时清理；自动迁移关闭时需执行数据库初始化以创建新表。

## 出勤绩效规则配置

- 全员共用一套规则，计算方式可选按区间或按单位，统计单位可选比例或天数，统计方式可选出勤或缺勤；切换需确认，重新设置并保存后替换当前配置。绑定薪资字段后，创建明细时使用规则计算，不重算已有明细。
- 页面读取失败时显示错误和“重试”，一般错误恢复前不可保存；旧员工规则存在多套冲突时可由管理员重新配置。重新读取时若存在未保存编辑，可选择加载已保存内容或保留当前编辑。保存失败会提示错误，需排查后重试。
- 按单位时配置每 1 个百分点或每天的有符号绩效调整金额（最多两位小数），正数增加、负数扣减；比例小数按实际比例折算，例如 3.5% 按 3.5 个百分点。
- 按区间时，按比例出勤沿用原有 100% 全勤规则和 0–100% 连续区间。按比例缺勤的区间从 0% 到 100%，含下限、不含上限，最后的 100% 上限包含 100%。天数区间使用非负整数，含下限、不含上限，最高区间无上限。
- 应出勤天数为工资月份在员工入职日至已确认离职日期内的日历天数，扣除考勤设置的休息日期；实际出勤取该范围内状态不是休息、出差或请假且上下班卡齐全的天数，再加上已通过的出差日。请假日即使留有上下班时间也不计入。单卡计 0 出勤。应出勤为 0 或缺少记录时阻止计算。输入、日期范围、规则、匹配结果及金额写入工资快照。已写入的快照不改写。
- 新配置保存在 `hr_settings.payroll_attendance_rule_config`；旧配置在未保存新配置时作为按比例出勤读取。按区间、按比例出勤保存时同步旧键；按单位配置对旧配置接口返回冲突以免误读，旧接口保存会切回区间配置；其他统计模式对更早的旧读取接口返回冲突。员工原有定薪规则和历史批次保留。

## 加班绩效规则配置

- 单位固定小时，可选按区间或按单位；按区间保留原有的区间每小时金额，按单位配置统一每小时金额。切换方式需确认并重新设置，保存后替换当前配置。
- 区间从 0 小时开始连续衔接，最后一个区间无上限；小时金额为非负数，最多两位小数。按累计时长匹配单一区间，并以全部计费时长乘该区间时薪；单位模式使用统一时薪。
- 加班费只统计补偿方式为加班费的已审批、完整打卡，按上班卡月份归属，未结束则阻止生成明细；使用原始秒数计算并四舍五入到分。明细保存时长、当时规则、匹配区间及金额；规则修改不重算已创建明细。
- 当前配置存于 `hr_settings.payroll_overtime_rule_config`，不存在时读取旧键 `payroll_overtime_rules`；保存区间模式同步旧键，单位模式下旧读取接口返回冲突、旧写入切回区间。

## 存储与事务

- 模型存于 `hr_settings.salary_component_model`；员工固定定薪存于 `hr_employee_records` 的 `values`，老记录可按旧角色镜像读取。
- `hr_payroll_batch_items.model_snapshot` 保存字段名、固定值、扩展值、类别、固定合计、岗位和版本；固定字段手调记录首次原值及最近修改人、时间。字段编辑使用版本防止并发覆盖，事务内锁定批次及明细。历史明细快照为空时不改变旧金额。
- `hr_payroll_disbursement_records` 保存每个已发放批次的汇总与不可变完整快照，批次 ID 唯一；旧员工级 `hr_payroll_records` 不再用于新记录。
- 创建明细和修改模型先锁模型；修改、复核和删除锁批次。数据库结构由 `server/sql/schema.sql` 与 `server/src/shared/db/pool.ts` 的增量迁移维护。
- `attendance_overtime_punches` 保存加班打卡，工资计算按审批状态、补偿方式和工资月份读取。

## 主要代码与接口

- 服务端：人事批次和规则接口在 `server/src/admin/hr/hrLifecycleRoutes.ts`，薪资模型接口在 `server/src/admin/models-formulas/`，计算、模型和部分数据访问在 `server/src/domains/payroll/`，人事校验在 `server/src/admin/hr/hrPolicy.ts`。
- Web：工资批次和发放界面在 `web/src/modules/hr/payroll/`，定薪历史工具在 `web/src/modules/hr/employee-records/`，规则和薪资模型在 `web/src/modules/models-formulas/`，共享人事 API 在 `web/src/modules/hr/api.ts`。
- 出勤绩效规则：`GET/PUT /api/admin/hr/attendance-payroll-rule-config-v2`。比例出勤的区间模式保存时同步旧键 `payroll_attendance_rules`。旧列表和旧配置接口已移除。
- 薪资构成模型：`GET/PUT /api/admin/hr/salary-model`；固定组始终包含姓名、员工号和职务三个字符串身份字段，其余金额字段同步到员工定薪。
- 加班规则：`GET/PUT /api/admin/hr/overtime-payroll-rule-config`。区间模式保存时同步旧键 `payroll_overtime_rules`。旧列表接口已移除。已绑定加班费字段在创建明细时读取规则。
- 手工扣除写入接口已移除。历史明细快照里的 `manualDeduction` 仍从实发减去，模型同步保留已有手填扣除。
- 补充项：`GET /api/admin/hr/payroll-batches/:id/disbursement`、`POST /api/admin/hr/payroll-batches/:id/disbursement/fields`、`PUT /api/admin/hr/payroll-batches/:id/disbursement/items/:itemId/fields/:fieldId`。
- 发放与记录：`POST /api/admin/hr/payroll-batches/:id/disbursement/issue`、`GET /api/admin/hr/payroll-disbursement-records`、`GET /api/admin/hr/payroll-disbursement-records/:id`。
- 批次：`GET/POST /api/admin/hr/payroll-batches`（GET 可用 `month=YYYY-MM` 查询指定月份），`DELETE /api/admin/hr/payroll-batches/:id`，以及 `GET/POST /api/admin/hr/payroll-batches/:id/items`、`PUT /api/admin/hr/payroll-batches/:id/items/:itemId/fixed` 编辑固定字段、`PUT /api/admin/hr/payroll-batches/:id/items/:itemId/extended` 编辑扩展字段，以及删除明细与复核接口。一键添加使用 `GET /api/admin/hr/payroll-batches/:id/auto-preview` 预览、`POST /api/admin/hr/payroll-batches/:id/auto-items` 写入。服务端要求超级管理员权限。
