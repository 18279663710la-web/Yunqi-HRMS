# 薪资发放开发说明

## 功能与权限

Web 人事管理分为工资批次、工资发放和工资发放记录三个独立页面，仅超级管理员可访问。管理员创建批次并添加工资明细，复核后可按批次登记发放；也可按员工手工登记。同一员工同月已有记录时整批回滚，登记不执行转账。

## 薪资发放流程画布

- 位于“模型与公式 → 薪资发放流程”，使用 React Flow 画布。
- 预设六种节点：系统算薪、手动调整、复核、输出工资条、发送到对应员工的小程序端、导入其他字段。同一类型可多次添加。
- 主导航全局固定为仅图标，子栏目侧栏规则不变；点击模块时主菜单选中态移动到该模块，子栏目宽度按最长子模块名称动态计算。画布填充标题下方的可用空间，空间不足时保留最小高度并允许纵向滚动。支持从左侧一级工具条点击加号打开二级节点面板，将节点拖入画布，或点击节点后让预览跟随鼠标、再次点击画布放置；点击节点后二级面板自动收起。工具条同时提供选择和平移模式；节点可移动，从输出端口连接到输入端口，Delete 删除节点/连线，支持缩放平移和保存。
- 连线只做基础校验：禁止节点自连、禁止同一对节点重复连线；暂不校验环路。
- 单份流程保存在 `hr_settings.payroll_workflow`，包含版本、节点位置和连线；刷新后恢复。版本用于防止并发覆盖。
- 当前仅保存流程结构，节点功能尚未接入算薪、复核、工资条、小程序通知或字段导入。

## 模型和工资口径

- 固定薪资模型包含姓名、员工号、职务三个字符串身份字段及可配置的数字或字符串字段；职务取员工主档岗位。固定模型保存时员工定薪按字段名同步：同名保留、新增数字为 0、字符串为空、删除移除；类型变更只允许无损转换，无法转换时事务回滚。
- 固定和扩展字段均可配置数字或字符串，以及“收入”“扣款”或“仅记录”；字符串只能选择仅记录。考勤系统弹窗分别选择数据项和计算规则：出勤天数、加班时长直接输出为数字仅记录；出勤天数可绑定出勤绩效、加班时长可绑定加班绩效，结果为数字收入，每种绩效最多绑定一个字段。旧加班费数据项继续按原口径计算；旧配置未选择数据项目时保留但不查询。
- 新增工资明细时，系统从员工当前定薪中按名称取得固定字段，并依据用途计算；未绑定考勤的扩展数字字段初始为 0、字符串为空，由管理员在草稿中手工填写；绑定考勤的固定及扩展字段自动读取，扩展字段不可手改。固定字段和扩展字段、类别及当时岗位保存为明细快照，后续模型修改不会改变已创建的明细。历史没有模型快照的明细保留原金额，不提供扩展字段编辑。
- 应发 = 固定和扩展收入字段之和；扣除 = 固定和扩展扣款字段之和；实发 = 应发 − 扣除。仅记录字段不计入金额，金额按分计算，超出范围或扣除超过应发时拒绝保存。
- 考勤取值以工资批次月份和员工为参数，在单人添加、一键添加预览及确认写入时查询，确认时重新读取。出勤天数沿用现有考勤汇总：非休息日存在上班或下班打卡计一天；未完成的单卡要求先处理，使用当前考勤休息日设置。指定月份没有考勤记录会提示核实。加班时长统计已通过审批且打卡完整的实际时间（包括加班费及调休），按上班卡日期归属月份，小时数四舍五入保留两位小数；未结束打卡提示处理，无加班记录为 0。查询失败或不完整会阻止创建，批量操作不会部分写入。
- 保存的工资明细快照包含考勤来源、项目、月份和取值；考勤变化不会自动修改已创建的明细或已复核批次。
- 已绑定出勤或加班绩效规则的字段在新增明细时计算并计入收入；出勤绩效的负调整减少应发。修改规则不重算已有明细，已复核批次不能修改。
- 单独添加要求员工有定薪生效日期；一键添加还要求入职表已封存且合同编号、起止日期完整。批次内已有员工跳过；一键预览不写库，确认时事务内重新读取并计算。

固定和扩展字段（包括身份字段）可设置显示方式：无、仅显示、仅输出，缺省为无。目前该设置仅保存于薪资模型，不改变工资批次展示、计算或输出。

## 出勤绩效规则配置

- 全员共用一套规则，计算方式可选按区间或按单位，统计单位可选比例或天数，统计方式可选出勤或缺勤；切换需确认，重新设置并保存后替换当前配置。绑定薪资字段后，创建明细时使用规则计算，不重算已有明细。
- 页面读取失败时显示错误和“重试”，一般错误恢复前不可保存；旧员工规则存在多套冲突时可由管理员重新配置。重新读取时若存在未保存编辑，可选择加载已保存内容或保留当前编辑。保存失败会提示错误，需排查后重试。
- 按单位时配置每 1 个百分点或每天的有符号绩效调整金额（最多两位小数），正数增加、负数扣减；比例小数按实际比例折算，例如 3.5% 按 3.5 个百分点。
- 按区间时，按比例出勤沿用原有 100% 全勤规则和 0–100% 连续区间。按比例缺勤的区间从 0% 到 100%，含下限、不含上限，最后的 100% 上限包含 100%。天数区间使用非负整数，含下限、不含上限，最高区间无上限。
- 应出勤天数为工资月份在员工入职日至已确认离职日期内的日历天数，扣除考勤设置的休息日期；实际出勤取该范围内非休息日的打卡天数。应出勤为 0、缺少记录或存在单卡时阻止计算。输入、日期范围、规则、匹配结果及金额写入工资快照。
- 新配置保存在 `hr_settings.payroll_attendance_rule_config`；旧配置在未保存新配置时作为按比例出勤读取。按区间、按比例出勤保存时同步旧键；按单位配置对旧配置接口返回冲突以免误读，旧接口保存会切回区间配置；其他统计模式对更早的旧读取接口返回冲突。员工原有定薪规则和历史批次保留。

## 加班绩效规则配置

- 单位固定小时，可选按区间或按单位；按区间保留原有的区间每小时金额，按单位配置统一每小时金额。切换方式需确认并重新设置，保存后替换当前配置。
- 区间从 0 小时开始连续衔接，最后一个区间无上限；小时金额为非负数，最多两位小数。按累计时长匹配单一区间，并以全部计费时长乘该区间时薪；单位模式使用统一时薪。
- 加班费只统计补偿方式为加班费的已审批、完整打卡，按上班卡月份归属，未结束则阻止生成明细；使用原始秒数计算并四舍五入到分。明细保存时长、当时规则、匹配区间及金额；规则修改不重算已创建明细。
- 当前配置存于 `hr_settings.payroll_overtime_rule_config`，不存在时读取旧键 `payroll_overtime_rules`；保存区间模式同步旧键，单位模式下旧读取接口返回冲突、旧写入切回区间。

## 存储与事务

- 模型存于 `hr_settings.salary_component_model`；员工固定定薪存于 `hr_employee_records` 的 `values`，老记录可按旧角色镜像读取。
- `hr_payroll_batch_items.model_snapshot` 保存字段名、固定值、扩展值、类别、固定合计、岗位和版本；扩展编辑使用版本防止并发覆盖，事务内锁定批次及明细。历史明细快照为空时不改变旧金额。
- 创建明细和修改模型先锁模型；修改、复核和删除锁批次。数据库结构由 `server/sql/schema.sql` 与 `server/src/shared/db/pool.ts` 的增量迁移维护。
- `attendance_overtime_punches` 保存加班打卡，工资计算按审批状态、补偿方式和工资月份读取。

## 主要代码与接口

- 服务端：人事批次和规则接口在 `server/src/admin/hr/hrLifecycleRoutes.ts`，薪资模型和流程接口在 `server/src/admin/models-formulas/`，计算、模型和流程服务及部分数据访问在 `server/src/domains/payroll/`，人事校验在 `server/src/admin/hr/hrPolicy.ts`。
- Web：工资批次和发放界面在 `web/src/modules/hr/payroll/`，定薪历史工具在 `web/src/modules/hr/employee-records/`，规则、薪资模型和流程画布在 `web/src/modules/models-formulas/`，共享人事 API 在 `web/src/modules/hr/api.ts`。
- 出勤绩效规则：`GET/PUT /api/admin/hr/attendance-payroll-rule-config-v2`；旧配置接口兼容区间规则，更早的旧接口仅兼容按比例出勤区间规则。
- 薪资构成模型：`GET/PUT /api/admin/hr/salary-model`；固定组始终包含姓名、员工号和职务三个字符串身份字段，其余金额字段同步到员工定薪。
- 薪资发放流程：`GET/PUT /api/admin/hr/payroll-workflow`；单份流程保存节点位置和连线。
- 加班规则：`GET/PUT /api/admin/hr/overtime-payroll-rule-config`；旧接口 `GET/PUT /api/admin/hr/overtime-payroll-rules` 保持区间模式兼容。已绑定加班费字段在创建明细时读取规则。
- 批次：`GET/POST /api/admin/hr/payroll-batches`，`DELETE /api/admin/hr/payroll-batches/:id`，以及 `GET/POST /api/admin/hr/payroll-batches/:id/items`、`PUT /api/admin/hr/payroll-batches/:id/items/:itemId/extended` 编辑扩展字段，以及删除明细与复核接口。一键添加使用 `GET /api/admin/hr/payroll-batches/:id/auto-preview` 预览、`POST /api/admin/hr/payroll-batches/:id/auto-items` 写入。服务端要求超级管理员权限。

## 验证与回滚

在项目根目录运行 `npm run typecheck`、`npm run build:server`、`npm run build:web`。薪资相关隔离数据库集成测试在 `server/` 目录运行：

```powershell
npx tsx --test tests/payroll-model-calculation.test.ts tests/payroll-model-batches.integration.test.ts tests/payroll-auto-items.integration.test.ts tests/payroll-disbursement.integration.test.ts tests/payroll-global-rules.integration.test.ts tests/overtime-attendance.integration.test.ts
```

出勤与加班规则相关测试可分别在 `server/` 和 `web/` 目录运行：

```powershell
npx tsx --test tests/attendance-rule-modes.test.ts tests/attendance-rule-modes.integration.test.ts tests/overtime-payroll.test.ts tests/overtime-rule-config.test.ts tests/overtime-rule-config.integration.test.ts tests/payroll-global-rules.integration.test.ts
```

```powershell
npx tsx --test tests/attendance-rule-load.test.ts tests/attendance-rule-modes.test.ts tests/attendance-rules-view.test.tsx tests/attendance-rules.test.ts tests/overtime-config.test.ts tests/overtime-rules-view.test.tsx tests/models-formulas-page.test.tsx
```

测试需要可连接、具备创建和删除临时测试数据库权限的 MySQL 账号；测试使用独立随机库，不应将冒烟脚本或数据库重置作为清理手段。

代码与文档使用 Git 管理，回退前检查提交范围和工作区，避免覆盖其他未提交修改。Git 不包含数据库备份；规则配置和工资数据须按实际数据库管理方式处理。
