# 性能压测模块说明

## 模块定位
- 隔离环境的负载生成和合成数据准备；不属于线上应用，也不包含真实业务数据。

## 架构
- `Dockerfile` 构建现有服务的隔离镜像；压测脚本在专用容器中通过内部网络访问应用或测试数据库。
- 测试脚本限定数据库名称和容器别名，并要求显式隔离标记与测试凭据；此检查不能代替网络及数据隔离。
- 不复制实际环境文件、上传目录或个人数据；U9 原生驱动在本镜像中不执行安装脚本，不用于真实 U9 压测。

## 目录结构
- `fixture.cjs`、`approval-fixture.cjs`、`large-pdf.cjs`：合成员工、考勤、工资条、指定大小的测试 PDF 及审批历史。
- `load.cjs`、`upload.cjs`、`onboarding.cjs`、`overtime.cjs`、`expense.cjs`、`u9.cjs`：模拟请求；`duplicate.cjs`、`approval-duplicate.cjs`、`cross-check.cjs`：并发正确性和隔离抽查。
- `safety.cjs`、`safety.test.cjs`：隔离标记与凭据检查及测试；`parallel.cjs` 和对应测试保证并发失败时等待请求结果；`README.md`：使用步骤与限制。
- `observe.cjs`：可选的隔离环境事件循环和进程内存观测预加载脚本；未挂接到产品运行入口。
- `ai-mock.cjs`：只监听隔离容器回环地址的合成 AI 响应，用于外部依赖模拟，不提供真实建议。
- `u9-mock.cjs`：仅在隔离进程内替换 U9 网关响应；不能衡量真实 U9、SQL Server 或其隔离策略。
- `2026-11-08-首轮结果.json`：首轮压测工具汇总的原始指标，不含真实业务数据。
- `2026-11-08-持续资源采样.csv`：持续场景的容器资源采样，不包含业务数据。
- `2026-11-08-登录事件循环.jsonl`：带观测器复测登录时的事件循环采样。
- `2026-11-08-工作台员工查询观测.json`：员工读取语句的摘要计数对比。
- `2026-11-08-并发错误观测.json`：唯一键冲突和死锁的测试库观测摘录。

## 开发规范
- 使用 Node.js CommonJS 和现有服务依赖，不修改业务实现；不写入真实凭据、令牌、真实数据或个人路径。
- 新增场景须检查 HTTP 及业务结果，明确负载、样本、数据规模、超时和失败口径；错误和未完成场景不得计为成功。
- 数据操作仅针对专用容器和虚构账号；不得将 URL 改为生产服务或连接共享数据库。

## 常用命令
- 在项目根目录运行 `node --test 性能压测/*.test.cjs`；隔离环境构建和执行命令见本目录 `README.md`。
- 其他依赖、格式化和检查命令待确认。

## 修改指南
- 修改前阅读项目根目录约束和压测记录；维护本文件、README 与根目录压力测试文档的一致性。
- 不更改已收尾业务逻辑。脚本和结果必须注明测试简化及未覆盖范围；有依赖或镜像变动时重新验证隔离和请求语义。
