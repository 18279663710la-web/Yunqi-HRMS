# Web 管理后台模块说明

## 模块定位
- 面向管理员的浏览器后台，管理员工账号、考勤、组织、管理员及报销审批人；调用上层项目的服务端管理 API。

## 架构
- `src/main.tsx` 启动 React；`App.tsx` 定义路由和登录保护，`auth/` 管理登录状态。
- 页面经各业务模块的 API 和 `api/client.ts` 访问服务端；管理员 token 存于 localStorage，401 后返回登录页。
- 使用 React、React Router、Ant Design 和 Vite；开发代理将 API 和上传资源请求转到服务端。
- 组织架构不显示模块标题和表格外围卡片，顶部操作栏包含职务筛选及“编辑”弹窗入口；员工与账号、人事员工档案及考勤共用该职务目录，人事异动与定薪页选择同一员工主档职务，页签重新激活时刷新目录。
- 员工与账号页面允许超级管理员为在职业务员选择或解除 U9 唯一业务员 ID 绑定，候选项显示名称、编号、组织与 ID。
- `AdminLayout` 在顶部管理紧凑全局页面页签，页签栏底部有分界线，当前页签下方断开；管理员头像入口位于主侧栏底部。`AdminPageRoutes` 按各页签保存的路由渲染页面，仪表盘是常驻首页，切换页签保留组件状态且不会自动展开侧栏，关闭或刷新后未保存状态不会保留。

## 目录结构
- `src/modules/`：按仪表盘、员工、人事、考勤、模型与公式、审批、组织及管理员分组页面、专用组件和 API。
- `src/layout/`、`src/components/`：后台布局和共享组件；`src/api/`、`src/auth/`：公共请求及认证。
- `src/types.ts`、`src/utils/`、`src/styles.css`：类型、工具和样式；`vite.config.ts`：开发代理及构建。
- `tests/`：Web 组件、模型、工具与页签测试；`src/pages/` 当前仅有目录说明，没有页面源码。各业务和子模块目录职责见 `../docs/项目目录职责说明.md`。

## 开发规范
- 使用 TypeScript 和 React 函数组件，沿用现有 Ant Design、路由、接口及错误处理方式。
- 除非用户明确要求调整架构，页面、业务 API、专用组件及工具按 `src/modules/` 的现有业务和子模块组织；共享布局、认证、请求和组件分别沿用 `layout/`、`auth/`、`api/`、`components/`，不把业务重新集中到旧 `src/pages/`。
- 保持服务端权限为准及现有页面 URL、子栏目行为和全局页面页签的状态语义；跨模块能力按已有边界复用。移动或改名文件后检查 Vite 模块解析和页面加载，必要时重启开发服务器。
- 新增或调整业务目录时更新该目录和父目录 README、模块说明及项目目录职责总览，使其描述与实际代码一致。
- 新增模块子模块时，沿用 `src/layout/subModules.tsx` 的 `SUB_MODULES` 配置、AdminLayout 的覆盖式子栏和独立子路由；主菜单点击只展开/收起，全局页签用于切换已经打开的页面。
- 子模块标题使用 `src/components/SubModuleHeader.tsx`（样式类 `.submodule-header`）：`Typography.Title level={4}` 加底部分隔线，操作按钮通过 `extra` 放在标题右侧；薪资构成模型、工资批次和工资发放页面不显示标题，内容卡片不重复子模块标题。
- 依赖由本模块 `package.json` 和锁文件管理；统一格式化及日志规范待确认。
- 权限需由服务端保证，前端控制用于界面展示；不得在源码或文档写入凭据。
- 产品界面不添加说明性文字；必要的字段名称、校验提示和操作确认保留。

## 常用命令
- 在本目录运行 `npm install`、`npm run dev`、`npm run typecheck`、`npm run build`、`npm run preview`。
- `build` 包含类型检查并由 Vite 构建；当前没有单独的测试脚本。

## 修改指南
- 薪资构成模型、工资批次、工资发放、工资发放记录目前暂时收尾。后续优化其他模块时，不得改变这四个模块的现有业务逻辑，除非用户提出硬性且明确的修改要求。保护范围包括计算口径、字段与数据流、接口行为、批次复核及发放、工资条发送与下载、历史快照和导出；涉及共享代码、数据或接口时须保持这些行为兼容，并针对受影响链路验证。若其他需求确实必须改变上述逻辑，先说明影响并取得用户的明确要求，再修改。
- 变更页面时检查路由、接口类型、加载与错误状态；涉及权限或数据写入时同步检查服务端。
- 接口基础地址与开发代理分别在 `src/api/client.ts` 和 `vite.config.ts` 配置。
- 考勤设置使用腾讯地图 JavaScript API GL；通过 `VITE_TENCENT_MAP_KEY` 配置 Key，楼层仅供展示。
- 考勤设置分别配置同日上下班打卡结束时间及可选的具体休息日期；时间段开始自动使用上班、下班时间。
- 考勤管理的单日汇总默认查询今天，可选历史日期；筛选、状态统计、导出和更正使用所选日期的数据。
- 考勤页面顶部统计将未打上班卡和未打下班卡合并为“异常”，数量为两者之和；缺卡独立统计，明细和筛选保留原状态。
- 考勤明细和汇总独立显示加班标签、打卡时间与时长，可按加班筛选；普通考勤状态仍保留，打卡跨日时归属于加班上班卡日期。
- 超级管理员在“管理员账号”页面创建董事长小程序账号，该账号不计入员工和考勤统计。
- 审批管理按请假、报销、加班、出差、采购分为五个路由页面；超级管理员可为每类指定一名已启用小程序账号的审批人，请假、加班、出差及采购额外支持董事长账号；审批人可审批自己发起的申请。
- “人事管理”和“模型与公式”是仅超级管理员可访问的侧边栏栏目：点击主栏目在主导航右侧以覆盖方式显示全高侧栏，侧栏只显示子模块菜单，不显示模块标题和关闭按钮；主内容位置不变，侧栏以滑动动画展开或收起并支持减少动态效果；两个侧栏互斥，点击主栏目只切换侧栏、不跳转。选择子模块后侧栏自动收起；点击侧栏外区域或再次点击主栏目也可收起，侧栏外原点击操作仍生效；收起后侧栏不接受焦点。人事管理子模块为入职管理、员工档案、工资批次、工资发放、工资发放记录、离职管理，旧入口 `/hr` 跳转到入职管理，`/hr/payroll` 跳转到工资批次；模型与公式子模块为出勤率绩效规则、加班绩效规则、薪资构成模型、入职申请表设置、薪资发放流程，旧入口 `/models-formulas` 跳转到出勤率页面。
- “模型与公式”继续使用人事管理的服务端规则接口，返回工资批次页面时重新加载数据。
- 页面切换时应保留未保存的编辑状态；需要重新获取跨页面业务数据时，使用 `useWorkspaceActive` 在页签激活时刷新，避免重置表单。工资批次、发放记录和人事员工列表已按此处理。
- 报销审批页面的各项功能使用独立卡片并纵向排列；超级管理员可管理发票审批人和审批规则文本。规则用于 AI 预审及辅助建议，不自动决定审批结果。
- 人事管理仅超级管理员可访问，按入职管理、员工档案、工资批次、工资发放、工资发放记录、离职管理六个子模块分页；除工资批次和工资发放外页面内标题显示当前子模块名。支持手工登记入职申请，按现有员工查看封存的个人信息并维护合同信息、定薪与薪资构成；工资发放页面支持按月份选择已复核工资批次。
- 管理员先在员工与账号页面创建档案及小程序账号，然后在人事管理登记自助入职申请。
- 人事管理按员工查看合同、定薪历史及登记人事事件；工资批次按固定模型字段用途计算，并按数字或字符串类型填写扩展字段，复核后锁定，不自动付款。离职清单完成后可明确确认离职和停用账号，撤销离职不会自动启用账号。
- 劳动合同编号、开始日期、结束日期必填并校验先后；合同文件区域支持导入和下载 PDF、Word、JPG、PNG，文件选择后立即上传保存，合同信息使用右上角保存。
- 入职任务模板入口已移除；“模型与公式 → 入职申请表设置”可新建多份自助申请表模板，点击卡片选择现用模板，点击独立的编辑按钮修改名称和字段；登记申请使用现用模板，旧申请保留只读展示。
- 已有模板的编辑弹窗可按当前编辑内容导出 Excel 入职申请表及填写说明，导出不保存模板修改；生成依赖 ExcelJS，按需加载；导出表标注签名必填。
- 模板支持删除和“修改历史”查看；“现用”或仅剩一个模板时不可删除，保存携带版本号，冲突时提示刷新。修改历史展示新建/修改/删除、操作人、时间及前后字段，已删除模板的记录仍保留。
- 自助申请模板可添加表格字段并编辑子字段；字段类型包含字符串、数字、日期、单选项和表格，单选可编辑选项列表；申请详情按表格显示多行数据，并展示员工提交的照片、签名和声明确认状态。
- 已提交申请详情提供“打回重填”“填写历史”和“封存”；封存后无法打回，个人信息只读展示封存的申请，未封存显示空状态。员工档案独立显示个人信息、劳动合同、定薪、调岗与晋升、人事事件五个选项；定薪金额字段来自固定薪资模型，姓名/员工号不在表单重复展示；合同及定薪在选择员工区域右上保存。
- 模型与公式的出勤率、加班绩效、入职申请表设置及薪资发放流程页面显示子模块标题；出勤率与加班绩效页面不使用外围功能卡片，标题位于内容区左上方；出勤率和加班绩效规则的保存按钮、入职申请表设置的修改历史和新建模板位于标题右侧，内容始终展开。
- 薪资构成模型页面不使用外围卡片和页面标题，顶部操作栏提供创建固定字段、创建扩展字段、编辑和删除；选择字段后显示蓝框，点击空白处取消选择，固定组字段标红星。创建和编辑弹窗只显示当前字段，删除固定字段时提示会删除员工定薪中的对应值；姓名、员工号、职务不可删除，编辑时仅能修改显示设置。字段列表使用紧凑灰色表头和细网格，横向滚动条位于页面最下方；字段可拖动或通过左右方向键调整顺序，支持字段交错，保存顺序用于模型列表、工资批次明细和一键添加预览。其他字段支持数字/字符串、收入/扣款/仅记录和考勤接口；字符串只能仅记录。保存携带版本，固定组变动按字段名同步员工定薪且类型变化仅无损转换。显示设置暂不改变显示或输出行为。
- 薪资模型删除确认框内的点击保留字段选择，确认后只提交一次删除；取消或保存失败保留字段，成功后清除选择。
- 主导航全局固定为 72px 仅图标样式：隐藏品牌文字、菜单文字和底部说明，保留品牌标记、菜单图标和底部管理员头像，点击头像可修改密码或退出登录；子栏目覆盖侧栏从主导航右侧展开，点击模块时主菜单选中态移动到该模块，关闭后回到当前路由；子栏目宽度按该模块最长子模块名称计算，选项框统一为最长名称的宽度并保留间距；不提供展开主导航的交互，子侧栏不显示模块标题和关闭按钮。
- 薪资发放流程页面不使用外围卡片，React Flow 画布填充标题下方的可用空间，空间不足时保留最小高度并允许纵向滚动。画布工具栏支持添加、选择和平移，节点可拖入或点击后跟随鼠标再次点击放置；节点右侧加号可创建并自动连接后续节点，同一来源的多个后续节点自动错开。支持节点移动、端口曲线连线、节点删除按钮及 Delete/Backspace 删除，删除节点会移除关联连线；节点和连线的变更须保存才生效。单份流程保存到服务端，连线禁止自连和重复，暂不校验环路。节点功能尚未接入算薪或发放。
- 出勤绩效规则可选按区间/按单位、按比例/按天数和按出勤/按缺勤；按单位填写每个百分点或每天的有符号调整金额；切换时确认重置规则，保存后替换现用配置。加载失败时显示错误和重试，恢复读取时保护未保存编辑。按比例出勤沿用全勤及闭环规则；其他模式从 0 起连续覆盖，天数为非负整数且最高区间无上限。保存规则不会重算工资批次。
- 加班绩效规则支持按区间或按单位，单位固定小时；区间按总时长匹配单一时薪，单位模式填写统一时薪。薪资字段选择加班时长和加班绩效规则后，创建工资明细时计算收入；规则变更不重算已有明细。
- 薪资字段接口选择考勤系统时打开独立配置弹窗，分别选择考勤数据和直接输出、出勤率绩效规则、加班绩效规则；出勤规则只能配出勤天数，加班规则只能配加班时长。直接输出为数字仅记录，绩效为数字收入；已配置后可通过“配置”再次编辑，取消保留原配置，旧加班费配置按加班规则显示。
- 工资明细支持单人添加及一键添加，考勤字段在创建时自动取值，一键预览展示固定及扩展字段，自动取值的扩展字段只读；扩展数字字段初始化 0、字符串为空。工资草稿的固定薪资字段（含考勤和绩效结果）、手工扩展字段直接在表格单元格编辑，姓名、员工号和职务只读。固定字段手动调整仅影响当前明细，保留原值及来源，不联动其他字段。模型收入减模型扣款得应发；页面、合计及导出不再显示独立扣除和实发，服务端原数据保留。输入时预览行和批次应发并标记未保存，回车或失焦保存、Esc 取消，连续点击其他可编辑单元格时先保存前一项。保存后采用服务端结果；失败和版本冲突保留输入，冲突刷新最新明细后须按回车重试。保存或待处理编辑期间禁止复核等批次操作。草稿字段用途与当前模型同步，已复核明细保留快照；历史无模型快照的明细只读展示原有应发。
- 工资批次编辑预览调用薪资模型的金额计算工具，字段用途由模型快照决定；接口取值仅创建明细时获取，保存结果以服务端为准。
- 工资批次、工资发放和工资发放记录分别使用独立路由；工资发放页无标题及外围卡片，顶部可选择月份和当月已复核批次，选择后展示原有只读明细、分页及紧随表格的应发与实发合计。顶部添加批次共用的数字补充项，各员工独立填写；补充项在明细表、发放记录和 PDF/XLSX 输出中位于应发之前；回车或失焦保存、Esc 取消，失败保留输入，冲突刷新后重试。刷新保留横向滚动位置，浏览器会话恢复已选批次；切换月份清除记录。实发由服务端按分计算，显示设置仅保存。输出复用工资批次的 PDF/XLSX 布局并包含补充项，发放记录及输出中的应发、实发表头上边界对齐；发放后批次只读，不可重复发放。记录页按批次显示汇总，点击月份在独立页签查看只读快照；发放时先为每人生成并暂存单人 PDF，再由服务端原子发放及发送；单人工资条不含批次合计行。已发放批次可逐人重发，重新生成文件并触发新提醒。
- 同月可创建多个工资批次，历史列表、发放选择和记录显示批次编号，导出文件名包含批次编号；单人选择禁用当月已复核和当前批次员工，一键添加跳过当月已复核员工。复核冲突以服务端结果为准。
- 工资批次无外围卡片和标题；顶部为月份、创建、历史批次、复核、删除的紧凑操作栏，历史批次通过弹窗选择。明细表及一键添加预览按现用模型字段顺序展示，历史快照独有字段追加；姓名位于模型首位时固定在左侧，操作列固定在右侧。表格使用紧凑灰色表头、细网格和底部原生横向滚动条，保留分页；添加明细及合计位于底部。工资发放页同样无外围卡片并提供月份及已复核批次选择，其他人事子页面沿用原有卡片布局。
- 工资批次操作栏支持输出 PDF 和 XLSX：使用居中的“工资表”标题、月份说明、编号表头和黑色网格，包含全部已保存明细及合计，字段按模型顺序排列并追加历史字段，编辑未保存时禁用输出；合计行前三列及中间列分别合并，末尾应发列独立加宽。PDF 使用同一 XLSX 工作表的单元格格式、列宽及行高绘图，所有列位于同一页宽，仅按员工行纵向分页，文本不可选择；XLSX 保存数字类型。
- 员工档案提供调岗与晋升，显示变更前后快照和撤销入口；入职建档后仍可维护后续任务，申请列表展示任务进度。
