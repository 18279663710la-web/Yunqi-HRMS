# 云启科技 · 企业办公（小程序 + Web 管理后台）

考勤打卡 / 审批流程 / 公告通知 / 通讯录 / 发票识别与查验，以及员工账号与考勤的 Web 管理后台。

项目功能优化暂时收尾，后续按实际需求继续维护。阶段性收尾不表示待确认事项或未实现功能已经完成，具体约束与现状见项目及各模块 `AGENTS.md` 和开发日志。

整套系统为 **全栈 TypeScript + 本机 MySQL** 的前后端分离架构：

- **小程序端**：原生微信小程序 + TypeScript，页面 WXSS 保持原样。
- **Web 管理后台**：React 18 + TypeScript + Ant Design 5 + Vite。
- **后端**：Node.js + Express + TypeScript，REST API、JWT、角色权限、文件上传。
- **数据库**：MySQL `yunqi_office`，小程序与管理后台共用同一套表和数据；业务员分包通过服务端读取外部 U9 SQL Server。

## 四、快速开始

### 0. 环境要求

- Node.js 18+（已在 Node 24 验证）
- 本机 MySQL 已启动（默认 `127.0.0.1:3306`）
- 微信开发者工具（已登录）

### 1. 数据库配置

参考 `server/.env.example` 创建 `server/.env`，并设置本机数据库及账号密码：

```dotenv
PORT=3100
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=<在本地环境文件中设置>
MYSQL_DATABASE=yunqi_office

ADMIN_USERNAME=admin
ADMIN_PASSWORD=<在本地环境文件中设置>
ADMIN_NAME=系统管理员
DEMO_EMPLOYEE_PASSWORD=<在本地环境文件中设置>
```

> 端口用 **3100**，避免与本机 3000 端口上的其他服务冲突。
> 如果 MySQL 密码/端口不同，只改 `.env` 即可；数据库会自动创建。

### 2. 安装依赖

```bash
npm run install:all
```

会安装 `server/`、`miniprogram/`、`web/` 三个工程的依赖。

### 3. 建库 + 建表 + 播种

```bash
npm run db:setup
```

- 创建数据库 `yunqi_office`（utf8mb4）
- 执行 `server/sql/schema.sql`，并对已有数据库做幂等增量迁移
- 写入演示数据：6 名员工、6 篇公告、5 种审批类型、60 天考勤、今日上班卡、默认管理员和演示员工账号；不生成模拟审批单。

> 首次启动后端时也会自动执行上述检查；`db:setup` 主要用于首次初始化/排查。

### 4. 启动后端（终端 1）

```bash
npm run dev
```

看到以下输出即成功：

```text
[server] http://127.0.0.1:3100
[db] root@127.0.0.1:3306/yunqi_office
[admin] 已创建默认管理员
[ocr] driver=mock  [verify] driver=mock
```

### 5. 启动 Web 管理后台（终端 2）

```bash
npm run dev:web
```

浏览器打开 <http://127.0.0.1:5173>，使用默认管理员登录：

```text
账号：admin
密码：<在本地环境文件中设置>
```

首次登录后请在右上角「修改密码」中更换密码。

### 6. 打开小程序

微信开发者工具打开 **项目根目录**（不是 `miniprogram/` 子目录），编译即可。

- `miniprogramRoot: "miniprogram/"`
- 已启用 TypeScript 编译插件，无需手动执行 `tsc`
- `urlCheck: false`，本地允许 HTTP 请求
- 启动后进入登录页，使用员工账号登录；账号由管理员在 Web 管理后台创建
- 可使用预置账号 `chenyiran / <在本地环境文件中设置>` 体验

### 7. 真机调试

开发者工具默认连接本机后端。真机上的 `127.0.0.1` 指向手机自身，须将 `miniprogram/utils/request.ts` 中的 `DEVICE_ORIGIN` 配置为手机可访问的电脑局域网地址。

正式发布必须使用 HTTPS 域名，并在小程序后台登记 request / uploadFile / downloadFile 合法域名。

| `app_meta` | 数据版本等元信息 |

### 考勤数据说明

- 首次初始化会为演示员工生成最近 60 天的考勤，以及**今天的上班卡**（默认排除 U001，方便在小程序里体验打卡）。
- 管理员补卡 / 请假 / 缺卡登记直接写入 `attendance_punches`，小程序考勤页与 Web 后台实时共享。
- 新员工没有历史考勤：未标记为休息日的过去日期无记录时显示「缺卡」；当天两卡均未打且下班时段尚未结束时显示「未打上班卡」。
- 管理员可以在 Web 后台按月份、职位、员工、状态筛选，并导出 CSV。

### 演示数据重置

- 小程序「我的 → 重置演示数据」：重置公告、考勤及查验缓存；保留审批、发票、员工和账号。
- `npm run db:reset`：完整重置数据库（会清空员工、账号、管理员并重新播种）。仅建议在开发环境使用。

## 七、Web 管理后台功能

### 仪表盘

- 员工总数、启用账号数、职位分类及三类人数、待审批单据
- 今日考勤：已打卡 / 未打卡 / 休息 / 请假
- 最近公告（置顶、分类、发布人、阅读进度）、最近入职员工

### 员工与账号

- 按姓名 / 拼音 / 工号 / 手机号 / 登录名搜索
- 按职位（研发员 / 业务员 / 员工）与账号状态筛选
- 职位列显示「研发员 / 业务员 / 员工」三种类型（新增时选择；历史数据按部门自动归类）
- 新增员工：填写姓名、性别、职位（必选）、工号、手机号、邮箱、入职日期、部门负责人开关
  - 职位下拉框固定为「研发员 / 业务员 / 员工」三类，提交时持久化到 `employees.job_category`
  - 拼音根据姓名自动生成，不占用表单
  - 部门默认归入公司根节点
  - 职级/工位/直属上级使用默认值，不影响账号创建
  - 新增/编辑表单均不展示部门、职级、工位、直属上级、拼音（编辑时保留原值）
- 同时开通小程序登录账号：登录名、初始密码、启用状态
- 编辑基础资料（姓名、性别、工号、手机、邮箱、入职日期、部门负责人）；开通账号；重置密码；启用/停用账号
- 离职入口（占位）：员工操作菜单提供「离职」，打开离职流程预留面板；当前不修改员工状态、账号、考勤或审批数据，后续接入离职审批 / 交接 / 账号回收 / 考勤结算

### 人事管理与薪资发放

- 超级管理员可办理自助入职、查看已封存的个人信息，并维护劳动合同、定薪、人事事件及离职清单。
- 薪资发放统一设置出勤率绩效规则。规则 1 为全勤且不可删除，其余规则按出勤率降序首尾相接覆盖 0–100%，新增区间拆分最低区间；新增工资明细时按员工对应月份考勤计算，保存规则时同步重算未复核草稿，已复核批次保持原样。
- 草稿批次可删除；工资明细根据薪资模型计算应发，页面及导出仅展示应发。“一键添加”先预览满足已封存入职表、完整合同和定薪生效日期的员工。工资发放页面暂保留入口，历史发放记录仍可查询。
- 计算口径、数据结构、接口、验证与回滚边界见 [薪资发放开发说明](docs/薪资发放开发说明.md)。

### 考勤管理

- 考勤管理拆为「考勤组」和「考勤明细」两个子模块，独立路由 `/attendance/groups`、`/attendance/records`，页面无标题、按钮位于顶部功能区。
- 「考勤组」不分类型，每组可设置上班卡、下班卡时间段（开始与结束时间可自由设置）、公司日历、地图打卡点坐标和半径；每组通过「选择员工」分配成员（按组织、职位、员工三级筛选，每级支持全选），多个组同时生效。列表以单选行选择组后使用顶部编辑/删除。
- 同一员工只归属一个考勤组；未分配员工使用第一个考勤组（按创建顺序），完全无组时回退初始打卡设置。上班卡时间段不能与下班卡时间段重合或晚于下班卡时间段，中间时段不能打卡；时段包含开始和结束分钟，不支持跨午夜。
- 「模型与公式 → 公司日历」维护多条作息规则：不固定、每周固定（双休/单休/自定义星期）或按周轮换（大小周/单双休，含起始周），并可配置例外休息日期和例外上班日期（法定节假日、调休补班）；考勤组必须选择一条公司日历。
- 上下班卡互不依赖，仅允许在各自时间段内打卡；考勤状态为正常、未打上班卡、未打下班卡、缺卡、请假、休息。
- 配置 `web/.env.local` 中的 `VITE_TENCENT_MAP_KEY` 并重启 Web 服务以启用腾讯地图选点；也可手动填写 GCJ-02 坐标。定位失败、精度大于半径或超出半径时无法打卡。
- 小程序定位需要在微信后台完善位置权限和隐私声明，并在真机上测试。定位结果可能存在偏差。
- 「考勤明细」提供月份、职位、员工、状态筛选；考勤明细：日期、员工、职务、上下班时间、工时、状态、备注；月度汇总：正常 / 未打上班卡 / 未打下班卡 / 缺卡 / 请假 / 休息 / 出勤天数 / 累计工时；考勤更正：补录上下班时间、登记请假/缺卡/休息、填写备注；导出 CSV。

### 组织架构

- 将员工统一归入「研发员 / 业务员 / 员工」三类
- 顶部统计三类人数，支持按分类筛选
- 员工列表展示姓名、分类、手机号、入职日期与登录账号状态，不展示部门
- 新员工使用创建时选择的职位；历史数据在服务端按部门自动归类（研发/测试/产品设计 → 研发员；品牌/用户运营 → 业务员；人力/财务/行政 → 员工）

### 管理员账号（超级管理员）

- 创建 HR / 超级管理员
- 启用 / 停用
- 重置密码
- 当前登录账号不可停用；系统至少保留一个启用的超级管理员

## 八、小程序端功能

- **工作台**：问候、职位分类、负责人标识（仅负责人显示）、今日考勤、8 个快捷入口、待办审批、最新公告、下拉刷新
- **考勤打卡**：实时时钟、定位降级、打卡、今日状态、本周统计、考勤明细
- **审批**：待我审批 / 我发起的 / 已办结、动态表单、加急、同意、驳回、撤销、审批意见；新建请假单按下述规则流转。
- **发票**：拍照/相册上传、左上角二维码本地解码、连续扫码、查重、模拟查验
- **公告**：分类、搜索、置顶、已读回执、附件、订阅入口、分享
- **通讯录**：部门筛选、拼音搜索、字母索引、拨号、员工名片、汇报关系
- **我的**：资料（职位分类、按分类显示的负责人标识、工号/入职日期，不展示职级）、待办、今日考勤、退出登录、重置演示数据

### 请假审批（阶段性收尾）

- 普通员工请假交由同职位的唯一负责人审批；负责人请假交由董事长审批。审批人账号不可用或配置不明确时不可提交。
- 请假时长由起止日期和时间自动计算且不可修改：不足一天记 1 天，超过一天的余数满 12 小时进 1 天。结束时间必须晚于开始时间，服务端会重新计算。
- 董事长通过独立小程序账号处理分配给自己的负责人请假单；其他四类审批规则另行梳理。
- 请假通过后目前不会自动写入考勤，审批结果订阅消息尚未接入；普通员工的审批可见范围需后续完善，正式使用前需结合实际账号与真机验证。

## 十、数据层与鉴权

### 小程序

```text
页面 → services/<业务>/api.ts 或业务服务 → utils/request.ts → /api/**
```

- 启动后进入登录页；未登录时任何业务请求都会跳转登录页，不再自动登录。
- 401 先刷新 token 并重放；刷新失败则清空登录态并跳回登录页。
- Storage 只保存 access/refresh token 与当前用户，不保存业务数据。
- 「我的」提供退出登录，退出后清空 token 并回到登录页。

### Web 管理后台

```text
页面 → src/modules/<业务>/api.ts → src/api/client.ts → /api/admin/**
```

- 管理员 token 保存在 `localStorage`；401 清除并跳转 `/login`。
- `AuthContext` 负责登录态、当前管理员、退出。
- Vite 开发服务器把 `/api` 与 `/uploads` 代理到 `http://127.0.0.1:3100`。
- 生产部署：`npm run build:web` 生成 `web/dist`，用 Nginx 静态托管并把 `/api` 反向代理到后端；同时配置 `VITE_API_BASE`（默认 `/api`）。

## 十一、发票识别与查验

- **图片读码**：小程序在图片左上角用 Canvas + jsQR 读取支持的二维码，未读出时提示重拍或扫码。
- **保存图片**：识别出可用票号后调用 `POST /api/invoices/image` 保存图片，不执行 OCR；票面信息不完整时需人工核对。
- **自动填单**：报销金额 = 多张发票价税合计；费用日期 = 最早开票日期；报销类型按消费类型映射。
- **查重**：数电票按 20 位号码、传统发票按代码加号码匹配；本单重复及待审批/已通过硬拦截，已驳回/已撤销只提示。提交事务中按规范化发票身份加锁并再次查重，避免并发重复报销。
- **查验**：先查重，再按规则返回 `valid / notFound / mismatch / duplicated / limitExceeded / invalid / error`，结果缓存 24 小时。
- 当前 `OCR_DRIVER=mock`、`VERIFY_DRIVER=mock`，模拟 OCR 不能用于报销；内部查重通过不等于验伪通过。二维码仅支持部分逗号分隔格式，动态二维码与 PDF 尚不支持，真实 OCR 和验伪需要后续接入。

## 十三、生产环境检查清单

1. **修改默认密码**：管理员 `admin`、演示员工账号密码；更换 `JWT_SECRET`。
2. **移除演示入口**：`/api/demo/reset`、默认种子员工账号、演示考勤数据。
3. **HTTPS + 域名**：小程序 request/uploadFile/downloadFile 合法域名；Web 后台启用 HTTPS。
4. **数据库最小权限**：为应用创建独立 MySQL 账号，仅授权 `yunqi_office`。
5. **管理员安全**：Web 后台当前使用 localStorage + Bearer Token；生产可改为 HttpOnly Cookie + CSRF 防护、IP 白名单、MFA。
6. **员工账号**：强制首次登录改密、密码复杂度、登录失败锁定、限流。

9. **审计与备份**：保留 `admin_operation_logs`；审批、发票、考勤数据每日备份。
10. **接口限流**：登录、OCR、查验、补卡等接口增加频率限制。

## 十四、常见问题

**Q：端口冲突？**
A：后端默认 3100，Web 默认 5173。改 `server/.env` 的 `PORT` 后，同时修改 `miniprogram/utils/apiOrigin.ts` 的开发者工具地址和 `miniprogram/utils/request.ts` 的真机地址；Web 开发代理在 `web/vite.config.ts`。

**Q：Web 后台登录提示无法连接后端？**
A：确认终端 1 已启动 `npm run dev`，且 `http://127.0.0.1:3100/health` 可访问；终端 2 运行 `npm run dev:web`。

**Q：小程序没有数据？**
A：确认后端已启动、开发者工具未校验合法域名；真机需把 `DEVICE_ORIGIN` 改成电脑局域网地址。

**Q：忘记管理员密码？**
A：开发环境执行 `npm run db:reset` 会重建默认管理员；或直接在 `admins` 表删除该账号后重启后端（表为空时会重新创建默认管理员）。

**Q：员工账号能登录小程序吗？**
A：可以。小程序登录页使用 `POST /api/auth/password-login`，账号需由管理员在 Web 管理后台创建并启用。

**Q：重置演示数据会删掉我创建的员工吗？**
A：小程序里的「重置演示数据」不会；它重置公告、考勤和查验缓存，保留审批和发票。`npm run db:reset` 会完整清空并重新播种，请仅用于开发环境。

**Q：上传的发票图片在哪？**
A：`server/uploads/`，通过 `/uploads/<文件名>` 访问；`npm run db:reset` 不会删除图片，可手动清理。
