# 小程序模块说明

## 模块定位
- 原生微信小程序，供员工使用考勤、审批、公告、通讯录与发票功能；依赖上层项目的服务端 API。

## 架构
- `app.ts` 管理应用状态；`app.json` 注册页面和自定义 tabBar。
- 页面调用 `services/` 中按账号、工作台、审批、通讯录、考勤和公告拆分的 API，再经 `utils/request.ts` 请求服务端；员工登录态存于微信 Storage，401 时尝试刷新并重试。
- 入职申请普通字段和表格子字段支持附件，可从相册、拍照或聊天记录选择；每处最多 5 个、单个不超过 10MB。上传通过登录态接口，提交前等待上传结束，打回后回填兼容的历史附件。
- 通讯录按服务端职务目录筛选在职员工，列表和详情不展示部门名称；进入页面时刷新职务目录。
- `subpackages/business/` 提供业务员的 U9 应收单/收款单按记账期间、客户查询，应收单按单号查看本人表头和明细、回款通知留单，以及收款单、汇总 PDF 下载；自定义底部导航按当前职务显示业务入口，服务端独立校验权限和绑定。
- 发票组件使用 Canvas、`lib/jsqr.js` 本地读码，再保存图片并依次请求服务端查重和真伪查验；不调用 OCR。

## 目录结构
- `pages/`：各业务页面，通常由 TS、WXML、WXSS、JSON 组成。
- `components/invoice-uploader/`、`custom-tab-bar/`：复用组件及导航。
- `services/`、`utils/`、`types/`：接口、通用工具及模型；`lib/`：二维码解码库。
- 每个页面与业务服务目录的职责见 `../docs/项目目录职责说明.md`；保留现有页面路径，以免影响注册、跳转和分享。

## 开发规范
- 使用 TypeScript 和微信小程序原生页面、组件，沿用现有命名、样式和请求错误提示。
- 除非用户明确要求调整架构，页面维持 `pages/` 中的现有注册路径，业务 API 放入 `services/` 对应模块，公共组件、工具和类型沿用各自目录；不要把全部业务接口重新集中到单个文件。
- 复用 `utils/request.ts` 与现有登录刷新和入职引导；变更页面路径、服务端接口或模型时同步检查注册、跳转、分享和两端契约。
- 新增或调整业务目录时更新该目录和父目录 README、模块说明及项目目录职责总览，使其描述与实际代码一致。
- 修改 API 时优先复用服务及请求封装；不要将凭据写入源码或文档。
- 依赖由本模块 `package.json` 和锁文件管理；统一格式化与日志规范待确认。

## 常用命令
- 在本目录运行 `npm install` 安装依赖，`npm run typecheck` 做类型检查。
- 微信开发者工具打开项目根目录编译；无独立构建或测试脚本。

- 业务员 U9 业务模块功能优化收尾，页面全部标记固定：`subpackages/business/` 各页面布局、交互与展示字段均不再修改，除非用户提出硬性且明确的修改要求。下一阶段仅允许性能优化（如客户池缓存、请求合并、分包与图片加载），且不得改变页面功能与接口行为；涉及共享请求或登录态时验证受影响链路。U9 原报表导出尚未接入。
- 薪资构成模型、工资批次、工资发放、工资发放记录目前暂时收尾。后续优化其他模块时，不得改变这四个模块的现有业务逻辑，除非用户提出硬性且明确的修改要求。保护范围包括计算口径、字段与数据流、接口行为、批次复核及发放、工资条发送与下载、历史快照和导出；涉及共享代码、数据或接口时须保持这些行为兼容，并针对受影响链路验证。若其他需求确实必须改变上述逻辑，先说明影响并取得用户的明确要求，再修改。
- 员工与账号、人事管理两个模块的功能优化已完成，**后续优化不得修改这两个模块**，除非用户提出硬性且明确的修改要求。小程序侧属于这两个模块的现有行为包括：入职引导、填写和签名，工资条提醒、查看和下载，以及登录时对停用、锁定和已离职账号的判断。其他小程序页面仍可按用户要求修改，但不得改变上述行为。
- 考勤管理模块的功能优化已完成，**后续优化不得修改这个模块**，除非用户提出硬性且明确的修改要求。小程序侧属于这个模块的现有行为包括：打卡页、考勤记录页、加班打卡、拜访登记，以及工作台进入拜访登记的入口。其他小程序页面仍可按用户要求修改，但不得改变上述行为。
- 批次发放时自动向员工发送工资条，个人工资条 PDF 不含批次合计行。工作台入职检查通过后检查未读工资条，显示弹窗；重发版本可再次提醒。个人中心的“我的工资条”可查看历史，通过受鉴权下载和微信 PDF 查看器菜单保存；不将令牌放入 URL。
- 工作台“公告通知”快捷入口替换为“拜访登记”，打开 `pages/visit/visit`；拜访登记要求客户名称、拜访目的、现场照片和自动获取的当前位置，单次签到由服务端记录时间，仅用于查看和导出，不改变考勤。位置只读取 `wx.getLocation` 的经纬度并调用服务端逆解析为地图地点名称和地址，不允许地图选点或修改；未配置地图 Key、额度用尽或解析失败时显示“当前位置”。公告仍从工作台“最新公告”和 `pages/notice/` 进入；定位声明仅包含 `getLocation`。
- 修改页面时同步检查对应 WXML、WXSS、JSON；接口和模型变更需与服务端协调。
- 开发者工具通过 `utils/apiOrigin.ts` 固定使用本机后端；真机按“手动设置 > 缓存 > 候选地址”探测 `/health` 自动选择可用地址，校园网或热点 IP 变化时可在登录页长按底部手动覆盖，留空恢复自动探测。请求失败会清空缓存并在下次请求重新探测；手机仅使用 4G/5G 时无法访问电脑局域网地址，需连接同一 Wi-Fi、手机热点或 Windows 移动热点。调试及发布时仍需按实际网络和微信域名配置调整。
- 入职引导、填写和签名页面通过 `services/onboarding/onboardingRoutes.ts` 统一识别；迟到的待入职接口响应不得中断正在填写或签名的页面。
- 登录和进入工作台前检查本人待填写入职申请；有待办时进入 `pages/onboarding-required/` 引导页，点击后进入 `pages/onboarding/` 独立填写页，提交成功后进入工作台；无申请的员工正常进入。特殊董事长小程序账号已于 2026-11-15 下线，董事长由职务为董事长的普通员工承担，审批页恢复统一的三个页签和发起入口。
- 已提交入职申请被打回后，员工重新进入入职流程，按打回时现用模板重填，仅回填与新字段类型、选项和限制兼容的旧值及照片，签名不自动沿用，声明须重新确认；大照片可保留但不内嵌预览。
- 工作台检查失败时不展示主界面，允许重试；停留时定期检查新登记的入职申请，接口返回待完成状态时重新进入引导页。
- 自助入职表格字段可增加或删除多行；单选字段和表格单选子字段使用原生 picker，只能从模板配置的选项中选择；照片可拍照或从相册选择，签名在 `pages/onboarding-signature/` 横屏画板完成，通过页面事件回填入职表，取消时保留原签名；提交前必须勾选同意声明并手写签名，确认状态随申请提交。照片选填，照片和签名各限 1MB。
- 考勤打卡会请求高精度 GCJ-02 定位并提交精度；位置权限及隐私声明需在微信后台配置，楼层暂不校验。打卡点不再包含名称与楼层，定位卡显示打卡半径。
- 打卡类型与按钮可用状态、休息日期和打卡点按员工所属考勤组读取；页面每分钟刷新状态，休息日期无需打卡。
- 考勤页单独展示本人已通过审批且尚未完成的加班打卡；申请开始时间起可打加班上班卡，打卡后可跨日打加班下班卡，均沿用定位验证；每个申请独立一组卡，同时只能有一组进行中。
- 加班申请不展示补偿方式选择，新单由服务端固定保存为加班费。详情和列表不再展示补偿方式，历史单据里的该项仍保存在服务端。
- 申请页按已发布表单的字段顺序展示。报销的发票附件和补充材料，以及加班的加班日期、开始时间和结束时间，位置跟随该顺序；未发布报销仍把发票附件和补充材料放在填写项后面。同一员工不能提交与本人待审批或已通过加班时段交叉的申请，服务端在提交时拒绝。审批流转区显示当前路径上的具体审批人，不展示系统查验、AI 节点和分支。未发布类型仍显示原指定审批人。已发布类型提交携带发布版本与字段值；版本过期或未匹配分支时不能提交。待我审批、我发起的和已办结只显示本人发起或经手的单据，详情同样限于申请人和时间线上的审批人。报销原图使用服务端签发的短期地址预览。
- 请假时长由起止日期和时间自动计算且不可编辑；有效时间不足一天记 1 天，超过一天的余数满 12 小时进 1 天。
- 审批列表和详情展示服务端返回的申请人职位，不展示部门；演示重置保留审批及发票数据。
- 详情接口按视角裁剪流转过程：申请人且非时间线参与人时返回 `flowVisible=false`，时间线与当前节点为空，仅保留最终状态；被驳回时以 `finalComment` 返回驳回意见。时间线上的审批人视角保留完整时间线。详情页据此条件渲染审批流程区。AI 节点自动失败三次后跳过并进入下一人工审批，详情不再提供重试；此前已停在失败状态的任务仍显示重试入口。
- 报销添加发票后按当前匹配路径的系统查验开关查重和验伪。开关未返回或预览失败时两项都做。两项都关闭时，识别完成即可提交。模拟结果始终不能提交。提交时服务端按同一路径再次决定是否查重和验伪，最多同时查验三张，并按发票原顺序报告最先的失败，短时间内可复用真实结果。支持拍照、相册和扫码，当前仅解析部分逗号分隔二维码，数电票动态二维码及 PDF 支持待完善。
- 报销可上传并命名补充材料图片。扫码没有图片时无法提供发票原图，补充材料当前只支持图片。
- 已发布报销流程的 AI 节点仍由服务端异步处理，同一节点自动失败三次后跳过并进入下一人工审批。申请页不再提供手动预审，提交前预审接口已移除，详情页不展示 AI 建议。提交审批不自动预审。
- 图片读码仅尝试左上角区域的正常色二维码；二维码不在此区域或格式不支持时需要重拍或扫码。查重通过不代表发票已验伪。
- 发票工具台支持从相册选图或拍照后自动读码、解析，查重通过后由用户触发腾讯云查验；不提供二维码文本录入、内置样本或模拟查验。服务端未配置密钥时显示查验未配置。
- CRC 自检只针对已用本地样本验证的 `01/32`、20 位号码、八字段数电票：CRC-16/UMTS 计算包含 CRC 前的逗号；其他格式显示未验证。CRC 不用于判定发票真伪或阻止报销。
